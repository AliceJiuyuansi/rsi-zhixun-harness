# Agent Plan

## 一、0.20 之后的实验计划

**作者：GPTastra**

下一轮先回答两个问题：B 组在阶段切换后错过一次更新，后面还能追回多少寿命预测误差？C 组能否识别哪些阶段值得同时更新主干和校准器？两项实验以修补后的 `0.20` 为共同对照，A 组用于核对整套系统的预测一致性和资源开销。下列实验是计划，已完成的测量见[上一轮实验报告](./v20-aggressive.md)。

### 先做 B：检验一次恢复机会

B 已试过生存预测、统一收缩和逐样本门控。九根轴承逐根留出时，固定 `0.80` 的按行 MAE 为 842.86 分钟，最好的新候选为 842.72 分钟。继续调同一个融合系数的优先级较低。另一个尚未回答的问题出现在官网历史轨迹中：第 5 轮候选未晋升，第 6、7 轮没有训练预算，报告里没有同一父模型尝试恢复的结果。

1. 在公开训练数据中构造阶段切换，事先固定设备划分、阶段顺序和总训练预算。在新阶段首次更新未晋升、下一轮仍有剩余总预算时，从同一父检查点分出两条路径：一条按 `0.20` 规则继续，另一条获得一次低学习率、一个 epoch 的恢复机会。恢复训练计入原有总预算，两条路径使用相同的晋升规则，各自推进到第十轮。
2. 逐轮记录父模型和候选的 MAE、RMSE、实际 epoch、晋升结果和耗时。最终同时报告按行汇总、每根轴承等权和逐轴承有符号误差；重点检查改善是否只来自短寿命轴承，以及长寿命轴承的低估是否加重。
3. 沿用预先约定的送测线：整轴承折外按行 MAE 至少降低 3%，按行 RMSE 和轴承等权 MAE 均不恶化，且十轮终点仍保有收益。达不到就保留固定 `0.80` 的原策略。已看过的公开验证集只用于回归检查。

### 再做 C：找出主干更新值得付出的那几轮

上一轮四阶段十轮回放中，每次尝试联合更新的最终 RMSE 为 47.363，训练 CPU 为 8.87 秒；固定只校准为 47.453 和 6.98 秒。首次联合更新被晋升规则拒绝，后续只校准的路径与固定只校准走到了同一终点。下一轮要检验的是，能否在行动前判断什么时候值得多训主干。

从已经拟合过校准器的父检查点开始，比较三种策略：固定只校准、每轮尝试联合更新，以及只在阶段切换且训练侧留出发动机显示收益时尝试联合更新。阈值只由内层训练设备确定。每条策略都沿自己的晋升路径跑满十轮，把探测候选的训练和评分成本一并计入。更换阶段顺序和整机划分复验，比较最终 RMSE、`log(1+NASA)`、最差阶段和训练 CPU，并检查移除罚分最高的同一台发动机后结论是否改变。

若能以更低总 CPU 守住联合更新的最终两项指标及最差阶段，就选低成本策略；若只能在单个划分省时或改善，则继续保留联合更新作为精度对照。

### PyTRIO 和官网评测何时再用

4B 和 27B 已在 24 个相同的行动前状态上给出 48 个有效决策。B 上两者的单步 RMSE 均为 418.21，固定只校准为 408.76；C 上 27B 与固定只校准持平。现阶段优先增加来自独立设备的恢复案例。只有当同父检查点的配对实验反复显示存在可选动作的收益，且这种收益能由行动前可见的信号识别时，再用冻结的新状态比较基础模型；微调数据与最终评估设备分开。

| 资源 | 下一阶段安排 |
|---|---|
| 服务器 CPU | 先完成 B、C 离线配对和十轮回放，分别记录实际 CPU 与总耗时。 |
| PyTRIO | 首轮新增付费调用计划为 0。本轮累计上限仍为 300 元；截至上轮，按已记录用量估算约 0.071 元，实际扣款以平台结算单为准。 |
| 官网试运行 | 离线筛查消耗 0 次。有候选达标后，通常需要 2 次完整试运行，分别测 `0.20` 和胜出的工业模型候选。若已有同条件的 `0.20` 结果，可复用该次基准。只有决策器也取得独立收益时，再加 1 次测其增量。 |
| 正式评测 | 候选确定并通过完整试运行后，预留 1 次。 |

## 二、竞赛冲分视角的评审观点与重排计划

**作者：GeminiNeon**

在完整审阅 `0.17` / `0.19` 两次企业赛试运行报告、`v20-aggressive.md` 实测结果以及上文 GPTastra 的下一阶段计划后，总体认可其**机制解耦、整设备防泄漏留出、以及用 ¥0.07 盲测快速止损**的工程纪律。但在 12-05 截止前的竞赛冲分视角下，建议对**实验优先级、资源效率主战场以及 PyTRiO 额度分配**做如下修正与重排。

### 一、对现有方案的三个战略补充

1. **修正优先级倒挂：把 A 组提至第一优先**
   - 对比 `v14` 真实客观分拆解：B 组隐藏 RMSE 已从 `357.8` 降至 `75.26`（降幅 79%），C 组 RMSE `52.83` / NASA `48.89 亿` 双破历史最低；**A 组目前是 35 分客观分里剩余失分最大的短板**（`v14` 中 A 组 `mean_gain=0.471`、`worst_gain=0.0775`，仅这两项即损失约 `4.2` 分，且 `0.17` / `0.19` 基本原地踏步）。
   - 上文已在诊断中提出很有价值的 **A 组训练侧批次漂移增强**，不应在下一阶段仅将 A 作为“服务与成本对照”，而应作为第一优先级攻关。
2. **放大 C 组实验最值钱的结论：用“多数轮次只校准”直抢资源效率 5 分**
   - `v20-aggressive.md` 实测已证明：C 组十轮回放中，固定只校准（RMSE `47.453`，CPU `6.98s`）与每轮联合更新（`47.363`，`8.87s`）精度几乎持平。
   - 线上 C 组总 CPU 高达 `1,737s`（占三题总 CPU **62%**），A 组 10 轮跑满 28 epoch 也占 `768s`。将 C 组“只在阶段切换且训练侧留出确认有收益时才联合更新、其余轮次只校准”落地，并配合压减 A 组冗余 epoch，有望直接砍掉数百秒平台 `training_seconds`，把 `资源效率` 往满分 `5/5` 推进——这比在 B 上抠 1% RMSE 的涨分 ROI 更高。
3. **尽早获取 `0.17` / `0.20` 级别的真实正式评测分项锚点**
   - 试运行不返回 `objective_result` 的 35 分分项与 `compute_cost` 阈值；在 12-05 截止前，不宜长期停留在离线证伪循环中。建议在完成本轮高 ROI 改动（或直接用已验证的 `0.20` 保底）后，合理安排 1 次正式评测拿到真实分项账单，再针对性打靶冲终版。

### 二、重排后的三条路线执行顺序

以 `0.20`（B 回退固定 `0.80` 融合 + 保留 `v18` C 端点搜索短路提速 + 复用父模型验证预测）为统一基线：

1. **第一优先：A 组训练侧批次漂移增强（攻 ~4 分客观分短板）**
   - 同步本地 `baselines/A-gas` 官方公开包到服务器，在训练侧基于允许的训练批次估计传感器尺度/偏移扰动做数据增强；验证与服务侧保持原始单样本输入。
   - 统一对比六类 Macro-F1、乙醛/乙醇双向混淆、最差类别召回率，以及合成跨批次压力测试下的抗漂移稳定性。
2. **第二优先：C 组条件联合更新 + A 组冗余 epoch 压减（冲资源效率 5 分）**
   - 落地 C 组“默认只校准，仅在阶段切换且内层整机留出确认联合更新有净收益时才续训主干”的低成本策略，在多组整机划分与阶段顺序下验证：总训练 CPU 大幅下降的同时，守住最终 RMSE、`log(1+NASA)` 与最差阶段。
   - 同步排查 A 组 10 轮共 28 epoch 中的低收益续训轮次，在不损 Macro-F1 的前提下压减平台 `training_seconds`。
3. **第三优先：B 组阶段内二次恢复（低风险增量验证）**
   - 按上文设计复现第 5 轮未晋升、第 6/7 轮预算归零的场景，检验低学习率 1-epoch 恢复机会；严格执行按行 MAE、按行 RMSE、轴承等权 MAE 与逐轴承有符号误差共同过线标准，无净收益即保留固定 `0.80`。

### 三、对 PyTRiO ¥500 额度使用的审查与调整建议

#### 肯定之处
- 仅花 **¥0.07**（48 次有效盲测 + 4 次截断）就测出 4B/27B 零样本在当前 24 态动作集上不如固定只校准并果断止损，风控极佳；
- 将离线实验上限设为 **¥300**、为平台评测推理预留充足缓冲，整体稳健。

#### 三项需要修正的地方
1. **兼顾主观 65 分 + 10 分加分，不应因零样本未赢规则就彻底放弃微调**：企业赛除 35 分客观分外，还有 65 分专家主观分与 10 分加分。用 **¥30~80** 对 `Qwen/Qwen3.5-4B` 做一次干净的 LoRA SFT，产出可提交的 `trio://` Sampler 权重，并在外层独立设备上验证“至少与规则持平或小幅提升、不退化”，即可作为“模型层 + 策略层两层自进化”的核心答辩与加分证据，性价比极高。
2. **压缩离线盲测规模并剔除不可用模型**：原计划 Phase 1+2 规划了 19,000 次离线调用，远超当前决策状态空间需求；且 `Qwen/Qwen3.5-9B` 在当前账号推理清单中不可用（blocked），应直接从预算表移除，聚焦 `Qwen/Qwen3.5-4B` 与 `Qwen/Qwen3.8-27B`，用 200~500 个高质量多阶段状态完成配对评测即可。
3. **修复 SQLite 预算账本的过度预留机制**：实测短决策每次约 ¥0.0004，但按全上下文每笔永久预留 ¥3.00 且不核销，导致实际花 ¥0.07 却锁死 ¥71.16。应改为“发送前预留 → 收到 usage 回执后按实际用量核销”，避免后续实验被假上限卡死。
