## 决策依据

v4 三题完成十轮，A 宏平均 F1 为 0.867426，B MAE 为 251.697725 分钟，C RMSE 为 56.381900 循环，NASA 为 8.852668×10¹⁰。v1 的 A 达到 0.873469，十轮均晋升，用了 28 个请求 epoch。v4 的 A 有八轮晋升，用了 23 个。两次结果支持重新检验 v1 的 A 策略，无法单独证明更新本身有负收益。

v4 与 v2 三题隐藏指标相同。v4 三题墙钟之和增加 986 秒，CPU 合计减少 514 秒。因此 v6 同时记录迭代预算、CPU 与墙钟。

## 实施

| 任务 | 变更 | 验证重点 |
|---|---|---|
| A 气体分类 | 恢复 v1 已测预算形态。首轮 5 epoch，训练行数增长时 3，其他轮 1。学习率依次为 0.002、0.0015、0.001。恢复 v1 的宏平均 F1 验收容差 0.02，保留现有闸门与异常熔断。 | 比较 v1/v4/v6 的第 2、6 轮是否晋升、最终 F1 和消耗。 |
| B 轴承寿命 | 保留 v4 的训练规则；预测上界设为 1,200 分钟。 | 固定早期检查点，1,679 条公开验证中有 3 条被截断，MAE 546.08 → 545.83，RMSE 654.97 → 654.66。后续隐藏集按最终检查点评估。 |
| C 发动机寿命 | 从 v4 无工况校准的预测出发，将上界设为 260 循环。新阶段先用 1 个 epoch 探测。 | v3 的 145 上界已损害隐藏表现。新上界在固定第 3 轮模型上只影响 90/23,049 条。公开 NASA 下降约 0.38%，RMSE 上升约 0.004。 |

各题保持十轮。累计请求预算上限分别为 A 28、B 25、C 13，合计最多 66，等于 v4 的实际总请求。按数据增长回读状态并累计已用预算，失败的训练请求同样计入。B/C 的输出限制同时作用于检查点评估和逐条预测，使用各自的官方输入结构识别任务。

## 调试与复现

1. 在同一公开检查点测试一系列阈值。C 的 145 上界使 RMSE 51.691 → 58.158，NASA 4.321×10⁹ → 7.346×10¹⁰。260 上界使 RMSE 51.691 → 51.695，NASA 4.321×10⁹ → 4.304×10⁹。B 的 1,200 上界在起始与早期已选检查点上都只修改少数极端预测。[对照数据](../试运行证据/v6公开截断对照.json)
2. 用官方 SDK 1.0.4 运行 A/B/C 各十轮，并重载最终检查点预测。独立重跑 C 的前三轮后，对全部 23,049 条验证记录逐条调用预测入口，得到 MAE 37.862050、RMSE 51.694671、NASA 4.304258×10⁹。[逐条预测结果](../试运行证据/v6公开SDK复测.json)
3. 32 项单元测试通过，覆盖 A 的验收容差、B/C 两种输入结构、未知结构回归模型以及单条与批量预测。
4. 将官方 SDK 放到 `_sdk/contest-harness-sdk-1.0.4`，公开 C 包放到 `data/raw/official_c`。从项目根目录执行下列命令，B 对照将 C 换为 B 并使用对应数据包。比较脚本对同一回归网络重新计算各上界，输出每种阈值的触发数和误差。

```sh
python scripts/test_harness_local.py --dataset C --rounds 3 --stage-every 10 --stub empty --save-selected out/selected.npz
python scripts/compare_prediction_caps.py C data/raw/official_c out/selected.npz out/c-limit.json
docker build -f harness.Dockerfile -t zhixun-rsi-harness:0.6 .
```
