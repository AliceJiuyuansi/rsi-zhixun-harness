# 三题同轮约束选模（0.9 候选）

基线是 Git `bfd4fca`。不假定粘贴的试运行与此 Git 提交使用同一镜像。保留训练预算、学习率、特征、C 校准和推理出口。每轮只使用当轮已公开的数据；不读取隐藏标签，不按轮号硬选模型。设置 `RSI_RELEASE=0.8` 可运行旧选模对照；新入口和 Docker 构建参数默认 `0.9`。

## 原理与依据

在同一轮固定父模型和验证集，取已训练的 epoch 快照和一次原有的平滑候选。先按能否晋升排序，再在可晋升候选中最大化 A 的 macro-F1 / 最小化 B、C 的总体 RMSE。若都不合格，保留诊断快照但平台选择父模型。早停继续使用原主指标，当轮选模不增加训练 epoch。不同轮次的验证集可以变化，不对相邻页面行相减再晋升。

- **A：同轮可持平，不可明显退步。** 用 0 代替 −0.02（仅留 1e−9 数值误差）。已有[公开配对消融](../技术报告_v6对照与v7方案.md)三个训练顺序的最终 F1 差为 +0.013814、−0.000743、+0.001569。三种顺序并非三个独立批次；在 v6 平台归档的十轮上，没有一轮的已记录同轮增益为负。
- **B：先判可部署，再按总体误差排序。** v8 已有轴承分组门控，却在每轮内部只保留最低总体 RMSE 的 epoch；该快照若被拒，另一个分组改善且本可通过的快照就找不回来了。复用原有 70/30 分组门控和总体退步护栏，不改权重。原先总体最优且合格的 epoch 仍然优先。
- **C：风险约束覆盖每个快照和平滑候选。** 保留 v8 的相对 NASA 风险预算和晋升规则；先过滤同轮不合格的快照，再在合格者中选最低 RMSE。缺少有效的同轮 RMSE 或 NASA 对数时不晋升。不是把跨轮 NASA 升幅当作训练损害，也不是保证隐藏 NASA 单调下降。

`training.json` 和当轮 `configuration.selection_audit` 可查同轮父子指标。后者标识验证文件 SHA；`component_cpu_seconds` 分开计本进程的拟合、常规校准、常规验证、平滑校准及平滑验证。不含读取数据、写文件和宿主等其他开销，不能等同平台总 CPU。门槛平移、权重筛选的保证仅限当轮已评估的候选，不是对未来阶段或最终综合分的保证。

## 不用平台额度的验收

1. 在两个策略中固定同一公开父检查点、训练行、顺序、学习率和 epoch 数。单轮配对示例（输出目录须不存在）：

   ```bash
   python3 scripts/compare_paired_selection.py --dataset B --package /path/to/public_B --epochs 3 --holdout /path/to/disjoint_later_public_B.jsonl --output /tmp/B-pair
   ```

   A/C 同理。各臂用自己的晋升规则确定最终选中的父/子模型，再评估独立公开留出。后续公开阶段如果是累计数据，请提供真正独立的留出；没有留出只能诊断选模，不把它当成泛化成绩。单轮配对不代替十轮轨迹。

2. 如持有合法可用的第 9 轮公开验证和父/子快照，用 `python3 scripts/audit_c_tail.py --parent parent.npz --child child.npz --validation public/validation.jsonl` 区分同轮模型变化和样本变化，核对高贡献发动机及预测偏高/偏低。
3. **暂不花平台次数。** 先在未参与选模的公开留出及多轮数据到达轨迹上检查 A 的 F1 不退步、B 的 RMSE 不退步、C 的 RMSE 与 NASA 能否同时不劣，并比较多次同机 CPU；若某题无收益或明显退步，不因三题代码同时完成就一起提交。这里的标准是保守的试运行准入条件，不是比赛官方评分公式。
