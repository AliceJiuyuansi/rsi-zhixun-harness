2026-11-25。本次仅做本地比较、修复、测试与源码交付，未构建镜像、未上传或调用平台评测。

## 结论

采用我们可运行的 v15 策略和完整算法实现，吸收队友材料的目录整理与源码说明思路，形成 v16 发布一致性修复版。没有足够证据把队友源码包视作更优模型，也没有增加未经验证的新训练损失或调参。v16 不是新增隐藏集成绩。

两份输入分开定义：我方 v15 为上次 outputs/v15 源码包；队友 v15 为用户提供“提交材料_v15/07-项目源代码.zip”。原始材料只读。比较依据是压缩包内实际文件，而非文件名或历史测试日志。

## 实际复现的故障

1. 原包设置 PYTHONPATH=harness 后 import contest_submission，错误为 `ModuleNotFoundError: src.harness.late_budget`。
2. 入口导入 paired_acceptance，但旧 round_controller 不提供；旧 trainer 也不接受入口传入的新版参数。补一个文件不能解决模块契约问题。
3. 将我们上一版选中的 C 检查点交给队友包的 Model.predict，在同一公开验证集 23049 行上，旧校准器直接调用抛 KeyError，Model.predict 捕获后悄然退回未经校准的 MLP：RMSE=51.846267，NASA=3.496776468e9。完整 v15/v16 对同一检查点为 RMSE=46.674885、NASA=7.674401416e8。

第 3 项仅是同一已有检查点的推理兼容性测试，不能写成“队友重新训练的 v15 成绩”。队友包当前无法启动，不能公平地执行完整训练性能或成本对比；“旧校准器更省 CPU”也尚未测量。

## v16 的具体修改

- 入口及镜像默认 0.16，沿用可运行 v15 的 C 调度，仍为 res_mlp_v2；A/B 决策、MLP/Adam/标准化、NASA 门禁和 13 epoch 上限不变。C 核心校准器、训练器及控制器均逐字节保留。
- `release_manifest.json` 固定本次发布的运行模块 SHA-256。`scripts/check_release.py` 先校验文件存在与哈希、Python 语法，再在新进程导入实际包并检查训练接口、默认版本、校准模式和可选检查点。
- 指定 --checkpoint 时，绕过预测接口的容错层显式调用校准器，避免旧模块不认识检查点却静默退回 MLP。此为验收工具，不改变线上预测容错行为。
- Dockerfile 的实际 COPY 后执行 image layout 预检并要求 SDK CLI 可导入。未满足则构建失败；这不替代完整 SDK 协议测试。
- `scripts/build_source_bundle.py` 明确导出目录，排除权重、数据、状态、旧 ZIP、SDK 和缓存；生成 ZIP 后，在临时目录解压，由新 Python 进程运行预检和完整单测，全部成功后才输出最终 ZIP。
- 增加七项测试：新进程导入、缺失/陈旧模块、Docker 路径映射、非法清单路径、不兼容检查点，Docker 构建上下文必需文件，以及 0.16 的十轮合成数据父子状态/finish 链。

哈希清单用于发现误混版本和遗漏，不是数字签名，也不能证明训练效果。源码预检缺 SDK 会明确警告；只有 --require-sdk 才将 SDK 缺失作为错误。

## 使用、回退与后续

解压新源码，先执行：
```powershell
py -3.12 scripts/check_release.py --root .
py -3.12 -m unittest discover -s tests -v
py -3.12 scripts/check_release.py --root . --checkpoint <已有检查点>
```
本机 py 启动器不可用，实际使用已安装 Python 3.12 的完整路径；日志真实附录。未增加运行时依赖。

准备官方 SDK 后按 `02-构建与验收.md` 构建并进行断网 describe/predict、平台 SDK 全流程。若改了代码，必须重新打包，不得手动复制单个入口到旧镜像：
```powershell
py -3.12 scripts/build_source_bundle.py --output <新的源码zip路径>
```
该命令会生成当前代码清单、解压校验并重跑单测；输出路径须不存在。若需复现原 v15，恢复整份我方 v15 源码/镜像与匹配状态，不要回退到队友这个混合包。v16 新增的是交付门禁，可通过恢复完整 v15 版本回退；切换 RSI_RELEASE=0.15 保留算法兼容，不移除这些发布检查。

风险：3-epoch 预留和有限探针仍是 v15 启发式，可能牺牲早期收益；13 请求 epoch 不是等 CPU 成本。回滚/kill/预算耗尽时，后几轮仍可能合法跳过。本版未为消除“未训练”文案而强行接纳坏候选。
