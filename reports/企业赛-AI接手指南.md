## 1. 我们交付什么

这是北京市大学生“人工智能+”创新大赛第 9 题“智训引擎”的企业赛。产线环境会随时间变化，例如气体传感器在新批次上的响应发生偏移。平台给出官方父检查点（本轮开始时的模型）和按阶段到达的数据，参赛系统要在标签、CPU 和大模型调用预算内，连续十轮自动维护预测质量。

| 任务 | 输入与目标 | 怎样发现退化 |
|---|---|---|
| A 气体分类 | 根据传感器观测识别六类气体 | 看六类等权的 Macro-F1、各类召回和混淆。准确率可能掩盖某一类全漏判。 |
| B 轴承寿命 | 估计轴承剩余寿命，单位为分钟 | 同时看 MAE（平均绝对误差）和 RMSE（对大误差更敏感），并检查单根轴承是否主导汇总。 |
| C 发动机寿命 | 估计发动机剩余运行寿命 | 看 RMSE 和 NASA 非对称罚分。少数发动机上的严重误差可能主导罚分。 |

**Harness** 是提交给平台的控制程序。每轮它读取当前允许的数据、父模型和历史，结合规则与基础模型建议，决定是否续训或校准；有候选时，在允许的验证数据上与同轮父模型比较，决定晋升候选或保留父模型。选中的检查点成为下一轮起点。三题分别推进。正式交付包括模型配置与可运行镜像、可查询的云端实验记录、匹配该镜像的运行说明。训练只用平台允许的数据，隐藏标签不参与调参。[赛事规则](https://rsi-index.115.zone/#rules) · [0.17 固定源码与入口](https://github.com/AliceJiuyuansi/rsi-zhixun-harness/tree/1ce12d72dbfcc2f87de60f04b283cb2ea1ee1699)

客观分共 **35 分**：平均增益 15、最差阶段 5、漂移后恢复 5、旧能力保留 5、资源效率 5。“最差阶段”描述漂移流中表现最弱的阶段。公开数据里的最低类别召回、最差设备误差可辅助诊断，各自的量纲和汇总方式不同。另有专家评分 65 分、最高 10 分加分，总分封顶 100。评委需要能沿一次决策找到假设、代码、父子检查点、续训证据、验证指标和用量。[评分项与证据索引](评分项-证据索引表.md)

## 3. 为什么选 `0.17`，哪些实验已经做过

下表是**官网试运行的隐藏集汇总**，可用于选基准。正式五项得分、排名资格和材料审核须从第 18 版正式回执读取。

| 指标 | `0.17` | `0.19` | `0.20 + A2` |
|---|---:|---:|---:|
| A 隐藏 Macro-F1 ↑ | 0.87397 | 0.87397 | 0.85314 |
| A 组 CPU 秒 ↓ | 767.76 | 743.49 | 761.61 |
| B 隐藏 MAE / RMSE ↓ | 48.71 / 75.26 | 58.15 / 75.69 | 48.71 / 75.26 |
| C 隐藏 RMSE ↓ | 52.83 | 52.83 | 52.83 |
| 全套平台训练秒数 ↓ | 1465.85 | 1589.80 | 1777.61 |

- **A 的统一训练上限已淘汰。** A2 从第 2 轮起把有训练的轮次限到 1 个 epoch。公开回放有 160 份 SDK 回执，两种顺序下选中的检查点均与对照一致。但这些顺序都源自同一个物理训练批次。官网第 3 轮原版晋升、A2 保留父模型，最终隐藏 F1 下降 2.08 个百分点。GeminiNeon 在计划第七节决定停止继续压 A 的 epoch，第六节中的早期建议已被取代。
- **B 保留固定 `0.80` 融合。** `0.19` 隐藏 MAE 变差，恢复原系数的组合回到了 `0.17` 的指标。九根轴承分别留出的实验里，分位数、生存预测、收缩、门控以及阶段内恢复均未通过既定联合标准。分位数方案曾改善设备等权 MAE，却恶化按行 MAE。重开 B 的既定筛选线是按行 MAE 改善至少 3%，并守住按行 RMSE 和设备等权 MAE。
- **C 保留有预算时尝试联合更新。** 三种整机划分、两种阶段顺序，共六个案例。固定只校准、条件联合更新均仅有 1/6 同时守住最终和最差阶段的 RMSE 与 NASA；探测也消耗 CPU。现有结果支持保留精度基线，C 的校准计算仍值得剖析。
- **单纯放大决策模型的收益有限。** PyTRIO 上的 4B 和 27B 各回答相同的 24 个冻结状态，48 次有效、零回退。B 上两者的平均单步 RMSE 为 418.21，固定只校准为 408.76；C 上 27B 与固定策略持平。即使逐状态事后挑最佳动作，B、C 的单步改善空间也分别只有 3.04%、0.32%。这一结论限于当时的动作集合、设备和父状态；学习新动作或改进整条十轮轨迹仍有研究空间。[离线消融](v20-offline-selection.md) · [PyTRIO 配对盲测](v20-aggressive.md) · [两位作者的决策顺序](Agent%20Plan.md)

```bash
cd ~/rsi-delivery/route-experiments/v17-formal

report = get(f'/runs/{rid}/report')

        run['contest_stage'], run['mode']) == (
    rid, 'ec074e6a4e180f08be1124a8c30a42d9', 18, 'enterprise', 'formal')

```

1. **运行中**：记录状态即可。写作时试运行已用 13/20，余 **7**；正式已用 3/4，余 **1**。此前两次正式属于校赛。后续以官网实时余额为准。
2. **完成并出分**：用原始响应保存 `v17-formal/official-report.json`。核对 `objective_result`、五项分数、可获得的分题／阶段增益、`eligible_for_ranking` 及各审核门槛，再看三题预测量、训练耗时和模型用量。若已完成但评分为空，继续读取同一 ID。若失败或取消，保存失败回执及原因，保留最后一次正式机会。
3. **定下一项实验**：用正式失分和已有回执选一个可以独立验证的因素。把结论及证据以 **GPTastra** 署名追加到协作分支 `docs/v20-aggressive-trials` 的 `reports/Agent Plan.md`，保留 GeminiNeon 和已有作者原文。新的实验建议与已经授权的评测分别记录。

## 5. 哪些改进值得用资源验证

| 问题 | 第一个可执行的对照 | 看到什么才推进 |
|---|---|---|
| 时间究竟花在哪里？ | 在原版 SDK 入口分段计时，覆盖读取数据、启动进程、载入检查点、逐条预测、训练、验证、校准。第 15 版十轮 A 的 `fit` 仅 3.87 秒，平台 A CPU 为 767.76 秒；C 有记录的五轮中，校准和平滑后再校准分别用了 69.69 和 56.92 秒。计时覆盖范围不同，差额的来源仍待实测。 | 优化一个实测热点。同输入下核对预测、选中检查点及晋升轨迹，再交替计时验证完整进程 CPU 有下降。 |
| A 能否识别新批次的乙醛？ | 公开留出批次的 109 条乙醛中有 108 条被判成乙醇。保持训练预算，在保留原始响应的基础上，单测样本内相对通道响应。 | 同时看两类的双向误判、六类 Macro-F1 和最低类召回。公开训练仅一批；跨物理批次效果交由试运行验证。 |
| 更新后是否遗忘旧阶段？ | **待验证的研究建议**：在规则允许范围内，从训练侧预留固定旧阶段样本。用同一父模型比较原晋升规则与加入旧阶段检查的规则，各自跑完整十轮。 | 旧阶段损失收窄，同时守住新阶段恢复和总预算；若拒绝变多、恢复变慢，撤下该规则。 |
| PyTRIO 微调值不值得？ | 先在训练侧找到“同一父状态下选不同动作确实会改变后果”的独立案例，再比较固定规则、基础 4B、小规模 4B LoRA。输入仅使用行动前可见信息，外层设备独立。 | 交付真实用量、独立设备表现和完整轨迹。若为答辩演示策略层学习，可评估精度持平时的成本或可解释收益；微调实验与加分之间尚无官方结论。 |
