# 真实数据实验报告 · XJTU-SY 轴承剩余寿命（proxy）

> 日期：2026-11-11
> 数据：XJTU-SY 轴承全寿命数据集（**公开替代数据，非赛题官方包**，见 `data/VERSION.md`）
> 结论位置：第 5 节；局限位置：第 6 节。**不要把本文数字当成官方评测成绩。**

---

## 1. 解决的是哪一层问题

官方数据包未开放，但"漂移 + 剩余寿命"的结构已经可以用 XJTU-SY 完整复现。
本文验证的是**系统层**：在真实的、自然发生的退化漂移上，
`静态 / 周期重训 / 触发式自进化` 三种策略是否跑得出符合直觉的差异，
以及成本口径能不能算清楚。不是刷 RUL 精度。

## 2. 数据与任务映射

| 项 | 内容 |
|---|---|
| 原始数据 | 15 个轴承，3 种工况（35Hz/12kN、37.5Hz/11kN、40Hz/10kN），从健康跑到失效 |
| 单快照 | 32768 点 × 2 通道（水平/垂直振动），25.6 kHz |
| 规模 | 9,216 个快照（另有 15 个轴承的索引），原始 12 GB |
| 任务 | **归一化 RUL 回归**：`rul_i = (n-1-i)/(n-1)`，1=全新，0=失效 |
| 模型 | HistGradientBoostingRegressor，CPU，单次训练 < 0.1 s |
| 性能指标 | `perf = -MAE`（越高越好）。MAE 单位是"寿命比例"，0.10 ≈ 平均误差为全寿命的 10% |

选择回归而不是分类，是因为官方赛题写的是"剩余寿命预测"；分类版本（健康/退化/失效三段）
保留在 `data.task: classification` 分支，随时可切。

## 3. 特征与流构造

每个快照抽 36 维（`src/data/xjtu.py`），两通道各 18 维：

- 时域 12：均值、标准差、RMS、峰值、峰峰值、偏度、峭度、峰值因子、波形因子、脉冲因子、裕度因子、过零率
- 频域 6：4 个频带能量占比（0–2k / 2–5k / 5–8k / 8–12.8k）、谱质心、谱展宽

构造流的方式（`configs/streams/xjtu_*.yaml`）：

- 用 `stride` 抽稀快照、`group` 把连续快照打成一个时间步
- 前 `warmup_steps` 步当作"部署时能拿到的训练集"，之后逐流推进
- 标签延迟 `label_lag=1` 步（模拟标注滞后）
- 漂移是**自然磨损**，不是合成注入

## 5. 结论

1. **漂移是真实且致命的**：部署后不更新，MAE 从早期的 ~0.05 退化到 0.34–0.45，
   也就是最后阶段预测误差接近半个寿命。这是"必须自进化"的最直接证据。
2. **两种更新都有效，但代价不同**：触发式精度最高（MAE 0.106），
   周期重训次之（0.145），但触发式花了约 1.8 倍算力。
   按赛题的"单位增益成本"口径，**周期重训反而更划算（92 vs 143）**。
   换到官方指标下，这条结论可能变——取决于 α/β/γ 的真实取值，这正是需要答疑的问题之一。
3. **回滚机制被真实触发**：3_4 与 2_3 各发生 1 次回滚，说明"晋升后变差→退回上一版"
   不是纸上机制，只是频率很低（8 次运行共 2 次），需要更多种子/更强漂移才能压测。
   目前的回滚依赖 `promote_margin=0.02` 和 3 步耐心，属于保守设置。

## 6. 局限（必须写进答辩，不要藏）

1. **不是官方数据**：任务类型、特征口径、评测脚本都可能与官方不同，
   数字不能和别的队伍横向比较，只能用于验证系统行为。
2. **单轴承单流**：每条流只是一个轴承的一生，没有跨轴承/跨工况的域偏移；
   真实产线会有"新设备/新载荷"这种更强的 covariate shift。
3. **warmup 假设**：默认部署时能拿到前 25–30% 寿命的有标签数据。
   官方场景可能只给很短的历史，或完全无标签，需要另做实验。
4. **模型很轻**：HGB 是 CPU 友好的占位模型，不代表最终精度上限；
   它的价值是让"更新/回滚/成本"闭环先跑通。
5. **成本口径是代理**：`weighted_cost = α·GPU秒 + β·标注数 + γ·Token`，
   α/β/γ 目前是 1.0/0.001/0.0，官方公式未公布。
   而且 GPU 秒是 wall-clock 计时，**同一矩阵换机器/换负载能差 ±15%**
   （2026-11-20 两次复测：periodic 92.4 → 114~122，trigger 143.1 → 175~179；MAE 完全不变）。
   → 结论"periodic 单位增益更便宜"稳定，但本文成本绝对值需空载复测后定稿。
6. **seed 不产生差异**：数据与训练都是确定性的，多 seed 只验证了可复现性，
   没有提供统计置信区间。要评估策略稳定性，应换轴承而不是换 seed。

## 7. 下一步（按优先级）

1. **跨工况流**：用 35Hz/12kN 训练、40Hz/10kN 部署，构造真正的域偏移，
   检验触发式是否能识别"不是磨损而是工况变了"。
2. **超参数层**：在模型层之上加第二层（学习率/叶子数/窗口长度的搜索），
   用同一套门控和成本账本，验证"策略层自进化"确实比固定超参好。
3. **Harness 层**：把"诊断→选动作"从规则换成 LLM 可调用的工具集，
   但保留白名单/幅度上限/次数上限/kill-switch/审计日志五件套。
4. **SwanLab 云端**：登录后把这批 run 重放到 `rsi-zhixun` 项目，
   作为"完整实验记录"的第一次真实演练。
5. 官方数据包一旦开放，**优先重跑第 4 节**，把本文降级为"系统验证"。
