## 0. 先说三句话

1. **Harness 不需要"训练"**。需要训练的是里面的**模型**；harness 是那套"发现问题→查表→做决定"的流程，你写的是规则和校验，不是梯度下降。
2. **数据处理 = 一条固定的五步流水线**，全部有现成命令，你只要会跑、会看输出。
3. **现在没有"官方测试"可提交**（平台没开放）。你能做的"测试"只有两种：本地自测（立刻能做）+ SwanLab 记录（这本身就是交付物之一）。

## 1. Harness 要不要"训练"？

### 1.1 先把"三种训练"分开

比赛里"训练"这个词被用在三个完全不同的地方，混淆是新手最大的坑：

| 说法               | 到底在训练什么                             | 用的技术                   | 谁在训     | 现在需要吗                        |
| ---------------- | ----------------------------------- | ---------------------- | ------- | ---------------------------- |
| **① 模型重训**       | 预测模型本身（我们的 HGB 回归器）                 | `model.fit(X, y)`      | 你的系统，自动 | ✅ 已在跑（`src/harness/loop.py`） |
| **② LLM 微调**     | 驱动 harness 的那个大模型（Qwen / PyTRIO 模型） | LoRA / SFT             | 你，手动一次性 | ❌ 校赛没额度，企业赛再考虑               |
| **③ Harness 自身** | **不训练**                             | 写规则 / 写提示词 / 写 JSON 校验 | 你，写代码   | ✅ 这就是"开发"，不是"训练"             |

一句话：**②是"教大脑说话"，③是"给大脑定规矩"。你现在做的是③。**

### 1.2 现在的 harness 长什么样（就是一段 if-else）

打开 `src/policy/policies.py` 的 `TriggerPolicy.decide()`，它读进来一堆数字，吐出"更不更新"：

```
输入（PolicyState）: 步数 step、已重训次数 retrains、上次重训步 last_retrain_step、
                    特征漂移 PSI、误差差距 error_gap、诊断结论 diagnosis
规则：
  1) 重训次数用完 → 不动作
  2) 距上次重训太近（冷却期）→ 不动作
  3) PSI 超阈值 或 误差差距超阈值 → 认为漂移了
  4) 预估能捞回的分数 < 最小值 → 不值得，不动作
  5) 否则 → 动作 = retrain
输出（GateDecision）: approved=True/False + 人话理由 + Action
```

这就是 harness 的核心。**你要"改进 harness"= 改这段规则**，比如：
- 阈值从写死改成"根据当前误差水平自适应"
- 加入成本判断（这次重训要花 3 秒，能捞回 0.02 分，值不值）
- 加入"连续两次回滚就永久降级为 periodic"这种经验规则

### 1.3 那"用 Qwen 决策"是什么意思？

把上面第 3 步的 if-else 换成：**把输入数字变成一段文字，发给 LLM，让它回一段 JSON，你再按 JSON 执行**。

```json
// 发给 LLM 的（示意）
{"step": 34, "psi": 0.27, "error_gap": 0.05, "diagnosis": "covariate",
 "budget_left": {"retrain": 5}, "allowed_actions": ["none","retrain","finetune"]}

// LLM 回的（必须这个格式，否则丢弃）
{"action": "retrain", "reason": "特征分布明显偏移，误差持续上升"}
```

**关键：LLM 只是"建议"，不是"权力"。** 它的输出要过三道关（见第 5 节），不合格就当它说 `none`。

### 1.4 如果你以后真要"训练"②（企业赛才需要）

不是必需的，但既然你问了，流程是：

1. **造训练数据**：拿 `scripts/run_matrix.py` 跑出的几百条"状态→最佳动作"记录（哪一步、什么指标、当时选了什么动作、事后误差降了多少），做成 `(prompt, 答案JSON)` 对。
2. **训一个小的**：PyTRIO `create_lora_training_client(base_model, rank=…)` → 组 `Datum`（`weights` 给 prompt 打 0、`target_tokens` 给答案打 1）→ `forward_backward` → `optim_step` → 存权重。
3. **接回来**：推理接口是 OpenAI 兼容的，把第 1.3 节那个 HTTP 调用换成本地模型即可。
4. **必须留 fallback**：模型输出乱码/超时 → 自动退回规则版 `TriggerPolicy`。

> ⚠️ 校赛阶段**没有 PyTRIO 额度**（`docs/00` p5），不要在这上面花时间。现在把 ③ 做到位，② 是加分项。

## 2. 数据处理：一条流水线，五个台阶

### 2.1 全景

```
原始振动 CSV (32768×2)
   │  ① 抽特征：每 1.28 秒的振动 → 36 个数字
   ▼
特征缓存 .npz  (1515 × 36) + 标签 rul
   │  ② 切流：stride 抽稀、group 打包、warmup 划训练/上线分界
   ▼
数据流 84 步，每步 6 个样本
   │  ③ 前 25 步当"历史"训练，后 59 步模拟"上线后陆续到来"
   ▼
模型 + 逐段评估
```

### 2.2 每步干什么、跑哪条命令

| 台阶 | 命令 | 产物 | 耗时 |
|---|---|---|---|
| ① 抽特征（全量） | `python scripts/build_xjtu_cache.py` | `data/processed/xjtu/*.npz` + `manifest.json` | ~2 分钟（8 进程） |
| 看懂①②③ | `python scripts/inspect_data.py` | 只打印，不写文件 | 2 秒 |
| ②③ 跑一条流 | `python scripts/run_stream.py --stream xjtu_3_4 --policy trigger --seed 0` | `experiments/<时间戳>-trigger-xjtu_3_4-s0/` | 5 秒 |
| 对比多策略 | `python scripts/run_matrix.py --streams xjtu_3_4 --policies static,periodic,trigger --seeds 0` | `experiments/matrix-<时间戳>/matrix.md` | ~30 秒 |
| 五件套自测 | `python scripts/check_guard.py` | 终端打印 9 类故障注入 PASS/FAIL | ~6 秒 |
| 导出给人看 | `python scripts/export_view.py` | `view/*.csv`（Excel 直接开） | 2 秒 |
| 看懂了什么 | `python scripts/report_run.py` | 终端打印"人话报告" | 1 秒 |

> Git Bash 里先 `export PYTHONIOENCODING=utf-8`，否则中文可能报 `UnicodeEncodeError`。

### 2.3 三个关键参数（都在 `configs/streams/*.yaml`）

```yaml
data:
  stride: 3        # 每 3 个快照取 1 个 → 抽稀，减少重复
  group: 6         # 每 6 个样本算"一步" → 一个时间窗口
  warmup_steps: 25 # 前 25 步是历史数据（模型初始训练用），后面才"上线"
```

- `stride` 越大 → 步数越少、跑得越快，但细节越粗
- `group` 越大 → 每步样本越多、误差越稳，但步数越少
- `warmup_steps` 越大 → 初始模型见得越多，后面就越"没什么可提升"，实验越平淡

**改完参数要重新跑流才生效**，改 `yaml` 不需要重新抽特征（`.npz` 不变）。

### 2.4 官方数据到手后要改哪里

只有一个文件：`configs/streams/` 新建一个 yaml，把 `data.kind` 从 `xjtu` 换成官方格式的 loader（需要在 `src/data/loader.py` 加分支），其余字段（`stride/group/warmup/task`）不动。

> 现在的所有数字都是 **proxy（XJTU-SY，公开数据）**，不是官方数据。写报告、答辩时必须标明，见 `data/VERSION.md`。

## 4. 怎么调试、怎么看结果

### 4.1 结果在哪（三个入口）

| 想看什么 | 去哪 |
|---|---|
| "这次考了多少分、它干了啥" | 终端跑 `python scripts/report_run.py` |
| 逐步明细（每步误差/PSI/诊断/动作） | `experiments/<时间戳>-trigger-xjtu_3_4-s0/metrics.json` |
| 各策略横向对比 | `experiments/matrix-*/matrix.md` |
| 用 Excel 看曲线数据 | `view/数据_*.csv`、`view/对比_*.csv` |
| 成本账本 | `<那个 run 目录>/cost.json` |

### 4.2 `report_run.py` 输出怎么读

```
【成绩单】
  平均误差 MAE : 0.129      ← 整个上线期间的平均误差。0.129 = 平均差 12.9% 寿命
  最后一步误差 : 0.217      ← 结束时差多少（通常比平均差，因为越接近失效越难猜）

【它做了什么】
  重训次数 7 / 晋升 6        ← 重训 7 次，其中 6 次通过了"比冠军更好"的门控
  回滚次数 0                 ← 晋升后如果持续变差，会自动退回去（保护机制）
  诊断分布 none=31 covariate=20 concept=7 label=1
                             ← 31 步没漂移，20 步是"输入分布变了"，7 步是"规律变了"

【花了多少】
  GPU 秒 2.58 / 标注 1465 / 加权成本 4.05
```

### 4.3 指标速查表

| 指标 | 含义 | 什么算好 |
|---|---|---|
| **MAE** | 预测剩余寿命的平均绝对误差（0~1 尺度） | 越低越好；<0.15 不错，>0.35 等于没学 |
| **perf** | 性能分，回归里 = **−MAE**（越高越好） | 越接近 0 越好 |
| **PSI** | 特征分布偏移程度 | <0.1 稳定，0.1~0.25 轻微，>0.25 显著漂移 |
| **error_gap** | 当前误差 − 上线时误差 | 持续为正 = 在退化 |
| **诊断 kind** | 漂移类型：covariate（输入变）/ concept（规律变）/ label（标签噪声）/ none | 不同类型该做的动作不同 |
| **单位增益成本** | 成本 ÷ max(性能提升, ε) | 越低越划算，是客观分的核心 |

### 4.4 排障表（照着查）

| 症状 | 最可能的原因 | 查哪里 / 怎么办 |
|---|---|---|
| 误差一路涨，`retrains=0` | 阈值太高 或 PSI 一直很小 | 看 `metrics.json` 的 `psi_max`；调低 `policy.psi_threshold` / `error_threshold` |
| 重训很多但 `promotions=0` | 挑战者没赢过冠军 | 看 gate 拒绝理由（`reason` 里有 `challenger=… vs champion=…`）；检查是否在同一 holdout 评分 |
| PSI 恒为 0.000 | 窗口样本太少（用了单步 batch） | 应使用 `stream.recent(step, window)`；`policy.window` 要 ≥ 20 |
| 结果每次跑都不一样 | seed / 配置不同 | `run_matrix` 固定 `--seeds 0,1`；单次跑加 `--seed 0` |
| `mean_mae` 异常小（<0.01） | 数据泄漏（训练集混进了测试时间） | 检查 `warmup_steps` 切分；模型只能看 `step < warmup` 的数据 |
| SwanLab 没记录 | 没登录 / `mode` 不对 | 本地看 `swanlog/`；登录后重跑会自动 online |
| 中文乱码 | 控制台 GBK | `export PYTHONIOENCODING=utf-8` |
| `docker pull` 超时 | 镜像仓库没加速 | 见 3.4 配置 `registry-mirrors` |

### 4.5 判断"这次改动有没有效"的方法

别凭感觉。**固定其他所有变量，只改一处，跑 2 个 seed，比较平均 MAE。**

```
改动前的均值 ± 波动        ← 我们的实测波动 std ≈ 0.007~0.010
改动后的均值
若差值 < 0.02 → 大概率是噪声，不算改进
```

这也是为什么阈值设成：`promote_margin: 0.02`、`min_estimated_gain: 0.015`。

## 5. 动作白名单是什么？有哪些？

### 5.1 一句话定义

> **白名单 = 系统"被允许做的事"的清单。LLM（或任何策略）只能在清单里挑，不能自己发明动作。**

类比：你想让实习生帮你干活，但你只给他 5 个按钮（不更新 / 重训 / 微调 / 换模型 / 调权重），
他按哪个都行，但**不能自己写代码、不能改数据、不能删文件**。这就是受控。

### 5.2 为什么必须要

题面要求"受控 RSI"，五件套：**白名单 / 幅度上限 / 次数上限 / kill-switch / 审计日志**。
没有白名单，LLM 一旦输出一个没实现的动作，系统就崩了 —— 而"无人干预跑完全程"是硬门槛。

### 5.3 我们的白名单（代码里已经定义，`src/schema.py` 的 `Action.kind`）

| 动作 | 做什么 | 成本 | 适用场景 | 风险 | 状态 |
|---|---|---|---|---|---|
| `none` | 什么都不做 | 0 | 没漂移；预算用完；没把握 | 无 | ✅ 已实现 |
| `retrain` | 用**全部**历史有标签数据从头重训 | 中（~0.4 秒 CPU） | covariate 漂移、自然退化 | 新模型可能更差 → 靠门控挡 | ✅ 已实现 |
| `finetune` | 在**最近一段**数据上增量微调（暖启动） | 低 | 漂移是渐进的、老数据仍有效 | 可能忘掉旧分布（灾难性遗忘） | ⬜ 待实现 |
| `swap_model` | 换成另一个模型/另一组超参（**这就是 HPO**） | 高（要试多组） | 参数漂移 / 系统性欠拟合 | 搜索成本高，需限次数 | ⬜ 待实现 |
| `reweight` | 给近期样本更大权重，重训 | 低 | concept drift（规律变了但样本还在） | 权重设太大会抖动 | ⬜ 待实现 |

**白名单之外、永远自动执行的保护动作（不由 LLM 选择）：**

| 保护 | 做什么 | 触发 |
|---|---|---|
| `rollback` | 退回上一个冠军模型 | 晋升后连续 `rollback_patience` 步变差超过 `rollback_threshold` |
| kill-switch | 停止一切更新，锁死当前模型 | 预算耗尽 / 连续异常 / 配置开关 |
| 幅度上限 | 单次动作的参数改动限幅（如 HPO 一次只改 1~2 个参数） | 每次动作前 |
| 审计日志 | 每次动作写一行 JSONL（时间、动作、理由、前后指标、成本） | 每次动作后 |

### 5.4 三层校验（LLM 说的话必须过三关）

```
LLM 输出 JSON
  ① schema 校验：kind 必须在白名单里，params 必须是允许的字段 → 否则丢弃，按 none 处理
  ② 策略门控：这次动作值不值？预算够不够？冷却期过了吗？ → 不过就 none
  ③ 执行后校验：动作执行完，在和冠军相同的 holdout 上比较 → 不更好就回滚
```

**这就是"受控"的全部含义：LLM 可以出主意，但不能越权。**

### 5.5 现在能选哪些

- 现在：`none` / `retrain`（`static` / `periodic` / `trigger` 三种策略都在这两个里选）
- 下一步（按性价比排序）：`rollback`（已实现但没进白名单枚举的说明）→ `finetune` → `reweight` → `swap_model`(HPO)

> 2026-11-20 起：`finetune` / `swap_model` / `reweight` 已经有白名单与参数范围（`PARAM_SPEC`），
> 但**执行器还没实现**；闸门会以 `not implemented` 拒绝，绝不会被静默当成 retrain 执行。

> 别一次全加。每加一个动作，都要能回答："它什么时候被选中？它比 `retrain` 便宜在哪？它会不会更差？"

### 5.6 一个更好的实现思路：把"选动作"做成 Decision Model

读了 PyTRIO 官方 Decision Model（PyTRIO-Jev）文档后，发现它和我们这里的问题**完全同构**：
"在固定候选里选一个"。

| 我们的问题 | Decision Model 的对应 |
|---|---|
| 动作白名单 `none/retrain/finetune/swap_model/reweight` | `choice` 题型的 candidates |
| 当前指标 JSON（PSI、error_gap、预算） | `state` |
| 该选哪个动作 | 预测 marker 位置的候选符号 |
| 门控/回滚 | 业务侧仍需保留，不交给模型 |

**好处（对客观分直接有利）：**

1. **结构上不可能越权**：模型只在 5 个候选符号上给概率，`argmax` 必然落在白名单里 → 第 5.4 节第①关变成"天然成立"，不用再写正则/JSON 解析兜底。
2. **token 成本极低**：推理是 `max_tokens=1` + 读 prompt logprobs，不生成解释文本。84 步决策 ≈ 每步几十 token，比"生成 JSON 说明"便宜一个量级。
3. **输出确定**：读概率分布 + 温度校准（Accuracy / ECE / Brier），可解释、可复现，比采样生成稳。

**要做的工作量**：候选符号映射（动作名 → 单 token）、模板里放 marker、训练 target 只在该位置置 `weights=1`、推理读 `topk_prompt_logprobs[marker]`。这些在 skill 的 `references/decision-model.md` 里有完整代码。

> 但这属于"企业赛加分项"。校赛阶段没有额度，**保持规则版**，把这套设计写进方案文档就够。

## 8. 术语一句话表

| 词 | 一句话 |
|---|---|
| 轴承 | 转动部件，磨损到一定程度就失效；数据是一条"从新到坏"的振动记录 |
| 快照 | 1.28 秒的振动采样（32768 点 × 2 通道） |
| 剩余寿命 RUL | 还能用多久，归一化成 1（全新）→ 0（失效） |
| 漂移 | 上线后数据分布变了，模型没跟着变，误差就涨 |
| PSI | 衡量"数据分布变了多少"的分数 |
| 诊断 | 判断是"输入变了"还是"规律变了"（决定该做哪种动作） |
| 门控 gate | 新模型必须先证明自己更好，才允许上线 |
| 冠军/挑战者 | 当前在用的模型（冠军）和候选模型（挑战者） |
| 回滚 | 上线后发现变差，退回去用老的 |
| Harness | 那套"发现→诊断→决策→执行→验证"的流程本身 |
| 单位增益成本 | 每提升一点性能花掉多少算力/标注/token |
