## v1 · 建立续训基线

**平台与实现**　镜像 0.1，初始实现 `97df9b5`。2026-11-21 完成试运行。

**方案与思路**　先验证平台能否连续十轮读取阶段数据、从父检查点续训、比较候选并交付可用模型。同时记录分类、回归和训练开销，作为后续改动的比较起点。

**实现手段**　通过平台 SDK 接入 A 分类与 B/C 剩余寿命回归。每轮按预算训练候选，在公开验证集评估后决定采用候选或保留父模型。

**实测与取舍**　A/B/C 各完成 10 轮。A macro-F1 为 0.8735；B MAE 为 506.67 分钟；C MAE 为 41.12 循环，NASA 为 8.85×10¹⁰。三题 CPU 时间分别为 993、368、1868 秒。A 连续采纳候选，B 从第 3 轮、C 从第 4 轮起持续拒绝候选却仍付出训练成本。因此下一版优先压缩无收益的续训，保留 A 的更新机会。[平台运行明细](../reports/trial_runs.md)

## v2 · 用跨轮证据分配训练预算

**平台与实现**　镜像 0.2，提交 `048bd98`。平台版本 `8636a3d…`，2026-11-23 完成试运行（run `2b638d5a…`）。

| 观察与改进思路 | 实现手段 | 验证时看什么 |
|---|---|---|
| 只看当前轮难以区分阶段变化与持续停滞 | 回读历史指标、特征与预测分布，计算跨轮漂移，使用连续未改善次数选择预算 | 阶段切换时的漂移值、规则和预算是否对应 |
| B/C 多次重训后仍沿用父模型 | A/B/C 单轮预算上限设为 5/4/3 个 epoch，加入停手与探针试训 | 拒绝连续发生后是否出现零训练轮，指标是否保持 |
| 回归最优值初始为 0，模型回复也可能被漏读 | 修正回归初值，兼容 reasoning_content，缺少模型文本时记录 unavailable | 首轮基准值是否有效，后续裁决是否能追溯 |
| 模型建议需要约束，候选收益需要可比较 | 将动作白名单、幅度、预算、停机开关和审计接入执行流程，在同一验证集比较父子模型 | 被拒的动作、候选和最终采用的检查点是否有记录 |

**验证与取舍**　基于 v1 历史信号的反事实回放，A/B/C 分别从 28/50/41 个 epoch 变为 28/17/18，估算节省 1291 CPU 秒。回放沿用旧候选分数，无法据此推断改变训练轨迹后的精度。

**实测（2026-11-23，run `2b638d5a…`）**　A/B/C 各完成 10 轮。相对 v1：A macro-F1 0.8735→0.8674（-0.69%）；B MAE 506.67→**251.70**、RMSE 708.58→**352.08**（约 -50%）；C 仍选第 3 轮模型，指标逐位不变。总 epoch 119→**66**（-44.5%），墙钟 8,160→**3,917 s**（-52%），CPU 3,229→3,044 s（-5.7%），token 22,366→32,087。停手规则在 B 第 4/6/7 轮、C 第 5/6/8/10 轮生效（7/30 轮）。结论：B 的收益来自“校准 3 epoch + 第 8/9 轮再训”，不是单纯少训；A 需把新阶段预算调回 3；C 的问题在预测上限，留给 v3。[平台运行明细](../reports/trial_runs.md)

## v3 · 收紧候选验收，限制 C 的极端预测

**平台与实现**　镜像 0.3，提交 `1702008`，平台版本 ID 为 `b318577fbc02cdfeb8504ac94c707c10`。11 月 23 日浏览器核对时校验通过。沿用 v2 控制器和训练预算。

| 观察与改进思路 | 相对 v2 的实现变化 | 待验证的收益与代价 |
|---|---|---|
| C 的 NASA 对极端误差敏感，过高预测可能主导总分 | 在预测出口将 24 特征 C 任务的剩余寿命限制在 0–145 个循环 | 对照 v1 同看 NASA、MAE 和 RMSE，检查限制高估是否引入低估；145 是本版策略参数 |
| 验收容差允许轻微退步，与保留较优父模型的目标冲突 | 分类和回归的退步容差降至浮点误差范围。晋升仍要求 macro-F1 至少增加 0.002，或 RMSE 相对下降至少 0.2% | 检查逐轮 gain、retain、promote，区分真正无增益和阈值拦截 |

**平台实测（2026-11-23）**　[试运行报告](https://rsi-index.115.zone/#runs)，run `27143ad15abd6f1a4daf998200625545`。三题各 10/10 轮，记录完整，共预测 14,773 条。A 最终选第 10 轮，accuracy 0.872902、macro-F1 0.867426；B 选第 9 轮，MAE 251.697725 分钟、RMSE 352.082921 分钟。两题均与 v2 持平（按平台展示精度）。C 仍选第 3 轮，MAE 41.120720 → 43.787114，RMSE 56.381900 → 62.881078，NASA 8.8527×10¹⁰ → 2.4400×10¹²（升至 27.56 倍，越低越好）。CPU 合计 3,075.16 秒，三题运行用时合计 3,729.87 秒，31,985 tokens。

**原因核查**　v3 收紧候选验收容差，晋升阈值未变。两版逐题的晋升轮次一致，门槛变化未带来新的模型选择。另一项变化在 24 特征回归的预测出口，训练端评估仍直接使用模型原始输出。官方 C 题说明定义公开完整轨迹的标签为 T−t，回归目标不封顶。将特定测试协议的末循环寿命范围推广为所有样本的上限，缺少依据。

**公开验证对照**　固定官方 C 起始 checkpoint，对 public/validation.jsonl 的 23,049 条样本只切换 145 上限。7,599 条真值超过 145（最大 434），7,736 条预测受到截断。MAE 38.90 → 41.19，RMSE 52.87 → 58.72，按逐样本 NASA 公式求和为 5.82×10⁹ → 7.37×10¹⁰。截断压低了高估惩罚，同时放大了长寿命样本的低估惩罚，后者主导总分。此对照使用公开起始模型；隐藏集逐样本误差归因仍不可见。

**取舍**　保留已验证的 B 预算策略。C 以 v2 无上限结果为基线，撤回 145 硬上限；后续输出变换先在同一 checkpoint 和公开验证集上经过实际预测路径比较 MAE、RMSE、NASA，再决定是否使用平台额度。

## v9.2 · 基于平台评测报告的 C 组 NASA 尾部校准与新阶段预算修复

- **版本与状态**　分支 `v9.2`（`RELEASE=0.9.2`），2026-11-24，基于 `v9`（`3209579`）迭代；本地全量单测与公开包闭环验证通过，待构建镜像并平台试运行。
- **方案与依据（来自平台 8 次试运行报告与 Run 0 / Run 1 / Run 3 逐轮日志）**：
  1. 最新 `0.9`（Run 0）隐藏集 C 组 NASA 为 `115.91B`、RMSE `55.43`，反而显著劣于 `0.7.2`（Run 1：`79.52B` / `54.45`）和 Run 3（`67.41B` / `54.96`）。根因在于真实 C 组 NASA 97%+ 来自极端低估尾部，而 `v8/v9` 校准器加入 `target < 0` 1.35 倍加权与 `[-3.5, +0.5]` 负向平移，加上 `±10` 硬截断，系统性放大了极端低估惩罚；
  2. `0.9` 的 `c_stage_probe` 将新阶段（`C-stage-02/03/04`，对应 R4/R7/R9）限制为 `1 epoch`，导致 R9 新数据使验证 NASA 暴涨 4 倍时，候选虽 1 epoch 即做到 RMSE（`50.468→50.443`）与 `nasa_log1p`（`23.191→23.066`）双降，却未达到 `0.2%` 或 `-0.15` 门槛而被淘汰，被迫用 R3 旧模型测隐藏集；
  3. 线上 `selection_audit.component_cpu_seconds` 显示单轮 `v8` 校准耗时已达训练的 ~6.5 倍（每 epoch 重复全量拟合 + 平滑候选重拟合）。
- **改进手段与思路**：
  1. **升级校准器并校正高估权重**（`vendor/contest_baselines/c_calibration.py`）：默认启用轻量双向残差 MLP `res_mlp_v1`（`[-120, +42]` 非对称截断、Tempered Entropic-NASA + MSE 复合损失、按工况双向 shift），基于公开 VAL + 3 折按发动机 OOF 消融将 `over_boost` 从 `1.65` 下调至 `1.15`（规避 `v8/v9` 负向偏置陷阱同时维持温和防高估），并将 `_best_shift_asym` 网格从 49 点精简为 25 点；保留 `spline_v2` 作为可通过 `RSI_C_CAL_MODE` 切换的解析备选；
  2. **恢复 C 组新阶段预算与合理化双降门控**（`src/harness/round_controller.py`）：将 `NEW_STAGE_EPOCHS["C"]` 与 `c_stage_probe` 从 `1 epoch` 恢复为 `3 epochs`（对齐 `0.7.2` 在 R4/R9 晋升的线上表现），并将 C 组 `nasa_bonus` 调整为 `gain >= 0.0 and delta <= -0.08`（RMSE 不恶化且 NASA 下降 ≥7.7% 即可晋升）；
  3. **多 epoch 校准重拟合节流**（`src/models/official_round.py`）：非 `v8` 校准模式在多 epoch 续训时，若中间 epoch 的未校准验证 RMSE 明显退化（`> 1.005×best`），跳过当轮校准重拟合以节省 CPU；`v8` 路径保持原样不变。
- **验证与结果（本地实测）**：
  - 76 项单元测试全通过，`py_compile` 无错；A/B 两题检查点 SHA256 与指标零回归；
  - 公开 C 组 3 轮闭环（对照 `0.9 (v8)`）：VAL RMSE `50.325 → 46.976`（-6.7%）、MAE `36.302 → 33.653`（-7.3%）、NASA `2.806×10⁹ → 1.267×10⁹`（**-54.8%**，`logN 21.755 → 20.960`）；3 折按发动机 OOF RMSE `54.087 → 52.080`、`logN 31.009 → 28.863`（**-88.3%**）；批量与逐行最大差 `8.53×10⁻¹⁴`。
  - 平台隐藏集表现、线上 CPU 耗时：待试运行验证。
- **取舍与下一步**：保持 A/B 逻辑冻结；先在平台对 `v9.2` 跑一次试运行，重点核对 C 组隐藏集 NASA/RMSE、R4/R7/R9 晋升情况与 CPU 耗时；若需要解析型对照，可通过 `RSI_C_CAL_MODE=spline_v2` 零改动切换。

## 源码 0.16 · B 组停滞后响应同阶段漂移

**本地联合验收结论**　保留 `0.16` 作为漂移回放开关，默认继续用 `0.15`。完整九折 LOBO、A 跨批次与 SDK 十轮的结论见[项目进度](status.md)。建议保留最后一次试运行。

- **问题与范围**　平台第 12 版的 B RMSE 为 357.785 分钟，第 9 版为 341.618 分钟。固定请求预算消融中，三种工况到达顺序和逐轴承留出下，只看总体 RMSE 与当前分轴承门控得到相同结果。公开包中复现了另一类故障：阶段 ID 和训练行数相同，连续两次候选被拒后遇到新的工况变化，停滞规则仍先返回零预算。分轴承门控和快照策略继续使用 `0.15`。[平台运行列表](https://rsi-index.115.zone/#runs)
- **检测与处置**　B 在同一阶段连续至少两次更新无收益后，若相邻训练窗口 PSI ≥ 0.25，且父模型 RMSE 比阶段内记录的最佳值高至少 0.2%，请求至多 2 个 epoch、学习率 0.0015 的恢复探针。两个信号用于触发，晋升仍按当轮同一验证投影的父子指标决定。执行受 B 全程 25 epoch、闸门及 kill-switch 约束。记录 `b_drift_recovery` 和同轮验收。模型建议 `hold` 时保留已触发的探针，显式 `rollback` 仍生效。
- **公开回放**　用 SDK 1.0.4 替身宿主、空模型回执和同一官方起始权重。每个工况从其公开训练轴承等距取 400 行，使用对应公开验证轴承的间隔取样，一半用于选模、一半用于最终评分。七轮保持同一 stage ID，前三轮工况 1、第 4 轮工况 2、第 5–7 轮工况 3。第 2、4 轮候选被拒；第 5 轮 PSI 为 8.8419，`0.15` 继续停训，`0.16` 的同轮 RMSE 从 815.159 降至 650.640 并晋升。

- **成本与限制**　连续切换场景总请求从 10 增至 16 epoch，其中 2 个用于本规则探针，后续 4 个来自原有概念漂移恢复规则且均未晋升。留出数据与选模数据来自同一公开轴承的不同时间点，单条轨迹只说明该故障场景的收益。81 项单测通过，A/C 各三轮本地 SDK 配对的训练轨迹、检查点和预测一致。Windows 上原有 CPU 计时断言偶发读到零，单独重跑全量通过。赛事隐藏得分、实际 CPU 和 Token 待验证。
- **复核优先级**　B 下一轮按整根轴承留出并覆盖往返切换，验证收益能否跨轴承复现；A 按气体批次和时间段留出，检查类别 F1 是否在漂移时集中下降；C 按工况比较恢复前后的 RMSE 和 NASA 尾部。平台复核优先核对 `b_drift_recovery` 触发、同轮晋升、总预算和三题指标。

- **方案与依据**　平台第 13 版（`036e178`）客观分 18.50/35：`resource_efficiency` 为 `0.00/5`（30 轮共耗 47,617 Token、训练 1,819.6 秒，系未关思考模式且 `res_mlp_v2` 每轮重复拟合 4 次），`mean_gain` 为 `7.64/15`（B 组增益仅约 4.17%，C 组 Stage 3/4 零晋升），`worst_stage` 为 `1.64/5`（B Stage 2 无适应，C Stage 4 R09 因 RMSE 波动 `-0.07%` 拒收了 `nasa_log1p` 降 0.18 的有效改进）。
- **改进手段与思路**
  1. **超紧凑 LLM 协议（`harness/contest_submission.py`）**：保留每轮 1 次真实 SDK 模型调用，显式传 `enable_thinking=False`、`max_tokens=64` 与约 216 字符的超紧凑提示，预计 30 轮总 Token 从 47,617 压至 ~3,000（硬上限 ~4,400）。
  2. **B 组纯训练侧符号一致 `log1p(RUL)` 校准（`vendor/contest_baselines/b_calibration.py`、`vendor/contest_baselines/model.py`、`src/models/official_round.py`）**：在训练集内筛选跨轴承相关性符号一致（`agree >= 0.80, |mean_c| >= 0.25`）的退化特征，按轴承等权（`bw=1.0`）求解符号投影 L2 Ridge，并在 `log1p` 空间与续训 MLP 几何融合（`alpha=0.80`）；保留 `v16` 的 `b_drift_recovery`，修复短寿命轴承和 Stage 2 增益不足。
  3. **C 组后期预算预留 + 快速校准 + NASA 容差（`src/harness/late_budget.py`、`src/models/official_round.py`、`src/harness/round_controller.py`）**：预留 3 epoch 至第 8–10 轮并支持停滞保护；`fast_c_calibration=True` 仅在最优 raw-RMSE epoch 后运行一次 `res_mlp_v2` 校准（单轮快 2.54×）；`c_nasa_tol=0.0015` 允许显著降低 NASA（`nasa_log1p <= -0.10`）且 RMSE 抖动在 0.15% 内的候选晋升。
  4. **A 组静默停滞跳过（`src/harness/round_controller.py`）**：在 `quiet_stall_a=True` 下跳过无数据增长/无阶段切换的停滞轮次，保留阶段切换 3 epoch 续训。
- **验证与结果**
  - `python -m unittest discover -s tests`：**93/93 通过**（含 `tests/test_v17_upgrades.py` 8 项新测试）。
  - SDK 1.0.4 `harness.py describe` 与 `harness.py predict` CLI 验证通过，A/B/C 单条与批量最大差均 `< 1e-12`。
  - 官方公开包 10 轮回放（`0.15` → `0.17`）：A `macro_f1=0.7187` 持平且 epoch `14→8`；B 验证 RMSE **`654.97 → 613.36`**（相对父模型收益 `+3.8% → +9.95%`，三根验证轴承全部下降）；C NASA **`8.030×10⁸ → 7.674×10⁸`**，epoch `12→8`（为 R8–R10 预留 3 epoch），总耗时 `77.60s → 63.13s`。
  - B 组 9 折 LOBO 交叉验证：Macro-RMSE `716.3 → ~426`（-40%），三阶段渐进回放 Stage 1/2/3 收益 `+13.3% / +11.4% / +9.4%`。
- **取舍与下一步**　已放弃的路线（不再尝试）：A 组 per-sample 校准头（跨批次退化）、C 组 `res_mlp_v3`（慢 1.5× 且验证不如 `v2`）、B 组未平衡 `bw=0.0`（伤害短轴承）。下一步构建 `zhixun-rsi-harness:0.17` 镜像并提交平台评测。

## 源码 0.18 · C 组端点偏移搜索提速

- **对照基线**　平台第 15 版企业赛试运行报告的源码版本为 `0.17`，本地配对基线为 `1ce12d7`。该提交的 `src`、`vendor` 和 `harness` 运行代码与算法改动提交 `24be80e` 一致。平台披露的材料未确定镜像精确构建提交。
- **实现**　`vendor/contest_baselines/c_calibration.py` 中复用固定预测分位数位置，先用原 RMSE 门槛淘汰端点偏移，再计算合格点的 NASA 指标。搜索网格、浮点运算顺序、并列处理、C 晋升门槛和 SDK 模型协议沿用 `0.17`。
- **本地证据**　SDK 1.0.5 替身宿主、官方公开数据、两版各 30 轮，逐轮选中检查点和最终预测 SHA-256 相同。C 评估单独留出 7,806 条整机分组记录，RMSE 46.042555、NASA 3.054814×10⁸，校准 CPU 15.42→13.31 秒。113,089 行端点搜索独立重复 9 次，CPU 中位数 0.266→0.141 秒，状态相同。
- **取舍**　三组公开发动机留出消融中，增加一次候选校准未带来额外晋升，因此只发布端点搜索提速。SwanLab 已补录原 `0.17` 官方试运行三题十轮报告。`0.18` 的隐藏成绩与线上计费待评测。

## 源码 0.19 · B 组负向校准条件融合

- **对照基线**　沿用源码 `0.18`（`c581f04`），线上对照是平台第 15 版企业赛试运行（`0.17`）。
