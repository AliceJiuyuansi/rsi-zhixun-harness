## 三、接口契约（先定接口，再各写各的）

> 用 dataclass 定义，Phase 1 第一天落成 `src/schema.py`。
> 字段可以加，**不能改语义**；改语义必须全队同步并更新本文。

```python
@dataclass
class StreamSlice:
    t: int                  # 时间片编号
    X: np.ndarray           # 预提取特征（或原始）
    y: Optional[np.ndarray] # 标签（可能延迟到达/部分缺失）
    meta: dict              # 工况、设备号、班次等

@dataclass
class Metrics:
    perf: float             # 主指标（acc/f1/mae，视任务）
    perf_delta: float       # 相对静态基线
    latency_p95: float
    n_samples: int

@dataclass
class DriftSignal:
    t: int
    feature_score: float    # 0~1
    residual_score: float   # 0~1
    is_drift: bool
    evidence: dict          # 每个特征的 PSI/KS、残差曲线摘要

@dataclass
class Diagnosis:
    kind: Literal["covariate", "concept", "none"]
    confidence: float
    reason: str             # 给审计日志和答辩用
    suggested: list[str]    # ["reweight", "retrain", "none"]

@dataclass
class Action:
    kind: Literal["none", "retrain", "finetune", "swap_model", "reweight"]
    params: dict            # 受白名单约束
    est_cost: float
    est_gain: float

@dataclass
class GateDecision:
    approved: bool
    reason: str             # "gain/cost=2.1 >= 1.5" / "budget exhausted" / "whitelist reject"
    action: Action

@dataclass
class CostRecord:
    gpu_seconds: float
    labels: int
    tokens: int
    wall_seconds: float
```

### 成本口径

```python
def unit_gain_cost(cost, delta_perf, alpha=1, beta=1, gamma=1, eps=1e-6):
    total = alpha*cost.gpu_seconds + beta*cost.labels + gamma*cost.tokens
    return total / max(delta_perf, eps)
```

- α/β/γ 未知时全取 1，**只比较组间相对值**
- 标注成本按"条"计，Token 按"千 token"还是"token"待 Q5 确认，**先按原始数记，换算在报表层做**

## 四、受控 RSI 五件套（架构级，不是可选功能）

| 机制 | 实现位置 | 具体做法 | 验收 |
|---|---|---|---|
| 白名单 | `src/policy/whitelist.py` | 动作枚举 `ALLOWED_ACTIONS` + 每个动作的参数名/取值范围 `PARAM_SPEC`；对外部提案（LLM JSON）用 `parse_proposal()`，**永不抛异常**，坏输入一律降级 `none` | `check_guard.py` F1/F2 |
| 幅度上限 | `src/policy/bounds.py` | 单次变更 ≤ 上版的 `amplitude_factor`（默认 2×），且同一动作最多改 2 个参数；超限截断并记 `bounds_clip` | F4 |
| 次数上限 | `src/policy/budget.py` | 终身 `max_retrains: 12` + 窗口内 `max_retrains_per_window: 8 / 40 步`（0 = 不限）；超限只能 `none` | F3 |
| kill-switch | `src/harness/killswitch.py` | `RSI_STOP=1` / `RSI_KILL_SWITCH=1` / `policy.kill_switch: true` / `STOP` 文件 / `max_wall_seconds` 超时 / 连续 `max_consecutive_failures` 次异常；**触发即锁死、不再恢复** | F5/F7 |
| 审计日志 | `src/utils/audit.py` | 每个 run 一个 `audit.jsonl`，append-only、逐行 flush：`run_start` / `action`（提案 + 门控理由 + 前后指标 + 成本）/ `reject_whitelist` / `reject_budget` / `bounds_clip` / `rollback` / `degraded` / `kill_switch` / `run_end` | F6 |

**唯一闸口**：`src/harness/guard.py` 的 `Gatekeeper.review()`。策略或外部 LLM 只能"提案"，
放行顺序固定：

```
提案 → kill-switch（锁死则 none）
     → 白名单（枚举 / 参数名 / 参数范围 / 单次最多 2 个参数）
     → 预算（终身次数 + 窗口速率）
     → 幅度上限（≤ 上版 2×，超限截断）
     → approved
```

失败一律降级为 `none`（保持当前冠军），执行后由 `guard.commit()` 记账。审计与门控状态落在
`<run>/audit.jsonl` 与 `<run>/guard.json`，`summary.json` 里同时留 `guard`/`audit` 摘要。

**验收方式**：故意喂非法动作、超预算、超次数、坏 JSON、断数据，系统都必须**降级而非崩溃**。
`python scripts/check_guard.py` 覆盖 9 类故障（F1 白名单 / F2 坏 JSON / F3 次数 / F4 幅度 /
F5 kill-switch 四来源 / F6 断流 / F7 连续异常自动锁死 / F8 数据缺失 / 健康跑到尾），
退出码 0 = 全部降级成功。

## 四点五、平台 Harness 契约（2026-11-20 新增，SDK 1.0.4）

平台只按三种方式调用镜像：`python3 /app/harness.py describe|train|predict`。
一次 `train` = 一个 **round**（检查点序号从 1 开始）；每数据集 10 轮。

```
/app          只读  我们的代码 + SDK + harness.py
/data         只读  train.jsonl / validation.jsonl（当前阶段公开投影）
/previous     只读  父产物（checkpoint.npz + 代码），摘要平台核验
/state        只读  上一轮原生状态
/workspace    可写  候选、状态副本
```

一轮里必须做的五件事（缺一即失败）：

1. 只从 `/data` 读训练/验证数据；
2. 从 `/previous/checkpoint.npz` **续训**（权重 + Adam + 标准化参数），不许从零训；
3. **至少一次真实模型调用** `rnd.model(...)`，`model_call_ids` 不能为空；
4. `rnd.submit_candidate(...)` 交一个 `/workspace` 下的新目录（含 `checkpoint.npz` + `training.json` + `history.jsonl`）；
5. `rnd.finish(selected_artifact_id=...)`——可选新候选、父模型或更早产物。

实现位置与契约：

| 文件 | 角色 |
|---|---|
| `harness/harness.py` | 官方入口模板，只做命令分发 |
| `harness/contest_submission.py` | `train(rnd)` / `predict(sample, model_dir)`，失败一律降级"保持父模型"并照常 finish |
| `src/models/official_round.py` | 续训原语 `continue_round(...)`，**早停 + 保留最佳快照** |
| `src/policy/strategy.py` | 漂移带 → 动作（none / finetune N 轮 / reweight） |
| `vendor/contest_baselines/` | 官方训练包副本（镜像自带，不依赖 `data/`） |

`continue_round` 的 `patience>0` 表示：连续 N 个 epoch 没有刷新最佳验证分就停，并保存**最佳那轮**的权重（不是最后一轮）。实测：固定 8 epoch 会把验证分刷到 0.7264 但伪隐藏 batch6 掉到 0.324；

早停 3 epoch 得 0.7257、耗时 0.02s vs 0.08s——**省钱且防过拟合，但不等于提分**。

本地彩排（不消耗平台试运行次数）：

```bash
python scripts/test_harness_local.py --dataset A --rounds 10 --grow        # 进程内假宿主
python scripts/test_harness_local.py --dataset A --rounds 3 --docker       # 容器内、--network none
python scripts/test_harness_local.py --dataset C --rounds 3 --max-train-rows 20000
```

### 4.6 v2 轮次控制器（2026-11-23 新增）

v1 试运行暴露了四个问题（回归初值、模型回复取不到、无收益仍重训、漂移参考不跨轮），
v2 把它们收敛到 `src/harness/round_controller.py`，`contest_submission.py` 只做 I/O 与闸门。

**状态 schema 2**（`/workspace/state-round-N/harness_state.json`）：

```text
metric / direction / baseline / best / last / last_gain / stalled / last_rejected
n_train / n_validation / stage_id
profile / baseline_profile / pred_profile      # 分位数直方图 + 预测直方图
updates / promotions / bounds / budget_steps / audit_events
decisions[≤10]                                 # 每轮的规则、PSI、模型裁决、前后指标
```

**预算表**（`choose_budget`，廉价优先）：

| 条件 | 预算 |
|---|---|
| 首轮 | A 5 / B 5 / C 3 epoch，lr 2e-3 |
| 新阶段 + PSI(上轮) ≥ 0.25 | A 3 / B 3 / C 2 |
| 新阶段 + 输入移动小 | 分类 2 / 回归 4（受上限约束） |
| 无新数据、指标回落 | A 3 / B 2 / C 2 |
| 上轮正收益、无停滞 | 分类 1 / 回归 3（校准） |
| 连续 ≥ 2 轮无收益 | 0（停手） |
| 停手后数据又增长 | 1（探针） |

**模型裁决**：`extract_text` 依次读 `content` → `reasoning_content` → 数组内容 → `output_text`；
要求一行 JSON，解析失败记 `model_action=unavailable`。模型只能 `hold` / 收窄 `train` / `rollback`，
不能放大预算；首轮与“新阶段+强漂移”不允许被 `hold` 掉。

**验收阈值**：分类 `gain ≥ -0.001` 可接受、`≥ +0.002` 才提交；回归相对 RMSE
`gain ≥ -0.2%` 可接受、`≥ +0.2%` 才提交。被拒候选不上传。

**回放**：`python scripts/replay_trial.py` 把 v1 报告逐轮喂给 `choose_budget`，
输出 `reports/v2_replay_v1.{md,json}`（反事实，不重新训练）。

### 4.7 v4/v5 候选（2026-11-24 新增）

**v4（默认）**：撤销 C 的 145 上限；`clip_regression_prediction` 只保留非负约束。
同时启用三项工程修复：

- `vendor/contest_baselines/data.py` 特征路径缓存（`lru_cache(2048)` + tuple path）；
- `summarise_history` 用每轮 `configuration.gain`，不做跨阶段分数差分；
- `contest_submission` 恢复 `kill_state`，训练成功/失败更新连续失败计数。

**v5（C 校准，可选）**：镜像构建参数 `RSI_C_CALIBRATION=1` 打开；默认 0。
仅对 24 特征 C 回归生效：

- 只用公开训练集，按第一项运行设置分工况估计传感器均值/方差；
- 5 节点分段线性残差，每样本最多修正 ±10；未见工况沿用父预测；
- 参数存于 `Model.meta["c_calibration"]`，随检查点保存；推理只依赖 NumPy；
- 校准拟合失败时回退到未校准模型，不中断训练。

**构建**：

```bash
docker build --build-arg RSI_C_CALIBRATION=0 -f harness.Dockerfile -t zhixun-rsi-harness:0.4 .
docker build --build-arg RSI_C_CALIBRATION=1 -f harness.Dockerfile -t zhixun-rsi-harness:0.5 .
```

**验收**：30 项单测；`check_guard.py` 9/9；两镜像断网 `describe`；
`0.5` 的 C 2 轮容器彩排 `calibrate_c=True`；v4/v5 的 C 全量 3 轮 + 23,049 条
逐条预测与公开结果一致。

### 4.8 v8 控制器

- 一次 run 只改**一个变量**（对照组原则）

- 本地跑完再手动补录（容易漏、容易编）
- 用不同数据版本的结果放在同一张对比表里
- 只保留最好的一次，删掉失败的 run（失败也是证据）

## 六、提交物规范

### 6.1 系统镜像

- 入口：`docker run <image>` 直接跑完一条流，**不需要传一堆参数**
- 自包含：权重、依赖、特征提取器、兜底模型全在镜像里
- 离线：无任何出网调用（可用 `strace` / 断网机器验证）
- 资源：CPU/内存/超时按未知规范取保守值，预留 30% 余量
- 日志：标准输出 + 落盘 `run.log`，方便评审排查
- 退出码：成功 0；失败也要输出"保持当前模型"的结果，**不要非 0 退出**

### 6.2 系统运行说明文档（`reports/系统说明.md`）

1. 系统做什么（一段话）
2. 架构图 + 数据流
3. 如何运行（一条命令）
4. 资源需求与耗时
5. 决策逻辑与受控机制
6. 实验记录在哪看（SwanLab 链接 + 项目结构说明）
7. 已知限制

### 6.3 实验记录

- 链接：团队项目 URL
- 查询依据：项目名、关键 run 名清单、对照矩阵表
- **提交前用无痕窗口验证链接公开可访问**

## 七、代码规范（轻量，够用即可）

- Python 3.10+，`from __future__ import annotations` 可选
- 全部随机源固定种子（`random` / `numpy` / `torch`）
- 配置用 YAML + dataclass 校验，禁止 `**kwargs` 满天飞

- 每个模块一个 `README` 或在文件头写 3 行说明
- 提交信息：`[阶段] 动词 + 对象`，例：`[p1] add stream evaluator`

### 开发环境一致性

- `requirements.txt` 锁版本（`pip freeze`）
- 可选：`Dockerfile.dev` 供开发用，避免"我这儿能跑"
- Windows 开发 + Linux 评测：路径一律 `pathlib`，不要写死 `\`
