# 08 · 三个任务怎么落地（A 气体 / B 轴承 / C 发动机）

> 场景：官方数据包里有三个任务，数据维度高、物理含义看不懂。
> 本文回答两件事：**① 我们要做哪些行为；② 看不懂数据时具体怎么操作。**
> 2026-11-20 起，随官方包到手持续修订。

---

## 0. 结论先行（三句话）

1. **你不需要理解数据里的物理量。** 你需要知道的是三件事：输入长什么样（几行几列、有没有时间轴）、输出是什么类型、指标怎么算。
2. **系统一行都不用重写。** 我们的 harness 是任务无关的：监测→诊断→决策→更新→验证→记账。换任务只换**三样东西**：数据加载器、指标函数、阈值量纲。
3. **三条任务里，B 我们已经跑通了 80%**（同一个"振动→剩余寿命"问题，我们现在用 XJTU-SY 代理的就是它）。C 需要新 loader + 非对称评分。A 是分类分支，代码里早就有 `task: classification`。

### 1.1 实测的公开划分（这是赛制信息，比数据本身重要）

| | train | validation | 划分方式 |
|---|---|---|---|
| A | **445** 行，全部 `source_batch=1` | **1244** 行，全部 `source_batch=2` | **按采集批次隔离**（传感器老化 → 天然概念漂移） |
| B | **7,032** 行，**9 根**轴承（1_1,1_2,1_3,2_1,2_2,2_3,3_1,3_2,3_3） | **1,679** 行，**3 根**（1_4,2_4,3_4） | **按整根轴承隔离** |
| C | **113,089** 行，FD001–FD004 各子集内切 | **23,049** 行 | **按整台发动机隔离** |

**B 的划分与本地 XJTU-SY 完全对得上**（逐根轴承行数逐一核对，误差为 0）：

```
Bearing1_1 123  Bearing1_2 161  Bearing1_3 158  Bearing2_1 491  Bearing2_2 161
Bearing2_3 533  Bearing3_1 2538 Bearing3_2 2496 Bearing3_3 371   ← 训练 9 根 = 7032 行
Bearing1_4 122  Bearing2_4 42   Bearing3_4 1515                  ← 验证 3 根 = 1679 行
```

→ **含义**：A 的训练集只有 batch 1（445 条），验证集是 batch 2；隐藏集极可能是 batch 3+。
也就是说三条任务考的都是**"训在旧分布、测在新分布"**，这正是我们 harness 的主场。
→ 我们本地已下载全量 XJTU-SY，**可以精确复现官方的 train/validation 划分**，甚至能猜出隐藏集大概是剩下的轴承
（1_5/2_5/3_5 那几根）。这是巨大的优势：**可以在本地做和平台同构的模拟评测**。

## 2. 三个任务的对照表（决定要改什么）

| | A 气体识别 | B 轴承健康 | C 发动机寿命 |
|---|---|---|---|
| 输入 | 一组传感器响应曲线（每条记录是一个"测量"） | 振动/温度时序（每个快照一段波形） | 多传感器时序（每个循环一行：21 维传感器 + 3 维工况） |
| 输出 | 6 类之一 | 剩余寿命（分钟，连续） | 剩余寿命（循环，连续） |
| 指标 | **Macro-F1**（越高越好） | **RMSE、MAE**（越低越好） | **RMSE**（越低越好）+ **NASA 非对称评分**（越低越好） |
| 我们现有代码 | `task: classification` ✅ 已有，但 perf 用的是 accuracy，**要换成 macro-F1** | `task: regression`，perf=−MAE ✅ **几乎直接可用** | 同 regression，但 perf 要换成 −RMSE 或 −NASA score |
| 特征 | 通用特征族直接可用（响应曲线的均值/峰值/斜率/面积） | 我们已有 36 维振动特征（时域 12 + 频域 6，双通道） | 需新写：每循环的 21 维原始 + 滑窗趋势特征；**多工况要做分组归一化** |
| 漂移来源 | 传感器老化（36 个月，天然 concept drift） | 磨损退化（run-to-failure） | 工况变化 + 磨损 |
| 改动量 | 小（指标 + loader） | **最小** | 中（loader + 特征 + 指标） |

## 3. "数据太复杂，我们不可能理解"——正确姿势

### 3.1 你不需要理解物理，只需要三张表

拿到任何数据，先做**侦察**，不要建模。三步，每步产出一张表：

| 步 | 看什么 | 输出 |
|---|---|---|
| 1. 形状 | 文件数、每文件行列、dtype、有没有表头、有没有时间戳列 | 一张 `清单.md` |
| 2. 分布 | 每列 min/max/均值/缺失率/唯一值个数 | 一张 `列统计.csv` |
| 3. 标签 | 标签在哪一列？类别名？连续值范围？和输入是不是一一对应？有没有 lag？ | 一段结论 |

**判据：只要这三张表能填满，你就"理解"到可以开工的程度了。** 其余物理含义（这个传感器测什么、那个频段对应什么故障）对建模**不是必需品**——树模型不需要你告诉它物理。

> 我们已有的 `scripts/inspect_data.py` 就是干这个的模板：换掉数据路径，按同样四步打印即可。

### 3.2 特征不靠理解，靠"通用特征族"

工业时序数据 90% 的信息被这四族吃掉：

| 族 | 具体量 | 一句话 |
|---|---|---|
| 统计 | 均值、标准差、最大最小、分位数、偏度、峰度、过零率 | 信号"大概多重、多抖" |
| 形态 | 峰值因子、脉冲因子、波形因子、裕度因子 | 有没有"尖峰冲击" |
| 频域 | FFT 各频段能量、谱重心、谱展宽 | 能量集中在高频还是低频 |
| 趋势 | 一阶差分、滑动窗口斜率、滑动窗口均值/方差 | 在变好还是变坏 |

再加一样：**相对量**（当前值 ÷ 基线值）。漂移场景里，"和刚开始相比变了多少"往往比绝对值更有用。

### 3.3 真正要防的不是"看不懂"，是这四件事

| 风险 | 后果 | 怎么防 |
|---|---|---|
| **数据泄漏**（用未来预测过去 / 测试集混进训练） | 分数虚高，隐藏流上崩 | 严格按时间切分；模型只能见 `step < warmup` |
| **指标方向搞反**（越低越好 vs 越高越好） | 门控反向，越训越差 | 所有 perf 统一成"越高越好"：`perf = -RMSE`、`perf = -NASA_score` |
| **阈值量纲错**（0.06 是归一化单位，换成"分钟"就失效） | 永远不触发或一直触发 | 阈值改成**相对量**：`k × 标签的标准差`（见 4.3） |
| **多工况没归一化**（C-MAPSS 有三档工况） | 工况变化被误判为退化 | 按工况分组做 min-max/z-score，或用工况作为特征 |

## 4. 代码层要改什么（清单，未实施）

### 4.1 指标：给 `step_perf` 加一个 metric 参数

现在 `src/eval/metrics.py`：

```python
def step_perf(task, y_true, y_pred):
    if task == "regression":
        return -mae(...)          # 只认 MAE
    return accuracy(...)          # 分类只认 accuracy
```

改成"任务 + 指标"双选择，并且**保证返回值恒为越高越好**：

```python
def step_perf(task, metric, y_true, y_pred) -> float:
    if metric == "macro_f1":  return  macro_f1(y_true, y_pred)   # A
    if metric == "mae":       return -mae(y_true, y_pred)        # B
    if metric == "rmse":      return -rmse(y_true, y_pred)       # C
    if metric == "nasa":      return -nasa_score(y_true, y_pred) # C（越低越好 → 取负）
    ...
```

配置里加一行 `data.metric: macro_f1 | mae | rmse | nasa`，对应 A/B/C。

**NASA 非对称评分（PHM08 标准式，需以组委会口径为准）**：设 `d = 预测 − 真实`

```
d < 0（预测偏小，报"快坏了"）：s = exp(-d/13) − 1
d ≥ 0（预测偏大，报"还能用"）：s = exp( d/10) − 1
总分 S = Σ s，越低越好
```

要点：**报"还能用"但实际坏了，罚得比反过来重**（分母 10 < 13）。这正好对应工业场景"漏报比误报危险"。接到我们的框架里就是 `perf = -S`，其余不动。

### 4.2 指标要报全，别只报一个

`summary.json` 里对回归同时记 `mae` 和 `rmse`（B 要两个，C 要 rmse + nasa）。原因：MAE 对异常值不敏感、RMSE 敏感——两者差距大说明有个别样本错得离谱，这在寿命预测里通常是"快失效段"。

### 4.3 阈值必须相对化（最容易翻车的地方）

现在配置里是 `error_threshold: 0.06`——它是在"归一化到 0~1 的寿命"这个量纲下定的。
换成"分钟"或"循环"后，同样的 0.06 **要么永远不触发，要么每步都触发**。

改法：配置写倍数而不是绝对值

```yaml
policy:
  error_threshold_rel: 0.15     # = 0.15 × 标签标准差
  min_estimated_gain_rel: 0.05
```

代码里 `err_thr = error_threshold_rel * std(y_train)`。这样 A/B/C 用同一套配置，不用为每个任务手调。

### 4.4 数据加载器：一个任务一个分支

```
src/data/loader.py
  ├─ kind: xjtu    ✅ 已有（振动 CSV → 36 维）
  ├─ kind: gas     ⬜ 每条记录一行（预提取特征）→ (N, d)
  ├─ kind: bearing ⬜ 同 xjtu 思路，换读取格式 + 单位换成分钟
  └─ kind: cmapss  ⬜ 每行 = 一个循环，21 传感器 + 3 工况 + RUL
```

每个分支只做一件事：**产出 `X (N,d)` + `y (N,)` + `t (N,)` 时间索引**。后面所有环节（切流、监控、门控、成本）一行不改。

## 5. 选哪条主线

**推荐：以 B 为主线，A 作为第二任务，C 排第三。**

理由：

| 任务    | 我们已完成                    | 还差                            | 风险  |
| ----- | ------------------------ | ----------------------------- | --- |
| **B** | 完整链路（数据→特征→RUL→三策略→断网镜像） | loader 换格式 + 单位换分钟 + 指标换算     | 低   |
| **A** | 分类分支代码已有                 | macro-F1 + loader（数据最简单：一行一条） | 低   |
| **C** | 只有回归框架                   | 新特征 + 多工况归一化 + 非对称评分          | 中   |

如果规则要求**三个都做**，就按 B → A → C 的顺序，每完成一条就锁死、写报告，避免三条都半成品。
如果规则是**三选一**，选 B，理由：唯一一条已有端到端证据链的任务。

> ⚠️ 这一条必须问清楚，见第 7 节 Q16。别猜。

## 8. 一句话总结

> 任务换的是**数据与指标**，不是系统。
> 我们要做的行为始终是那五件：**看数据 → 建基线 → 监测漂移 → 决定更新 → 记账验证**。
> 复杂的是数据，不是你的工作；数据看不懂是常态，**用侦察表代替理解，用验证集代替直觉**。
