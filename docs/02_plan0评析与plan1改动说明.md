# 02 · plan0 评析与 plan1 改动说明

> 对象：`../plan0.md`（2026-11-07 版，已存档不再修改）
> 产出：`../plan1.md`（当前执行计划）
> 日期：2026-11-11

---

## 一、plan0 做对了什么

先肯定，这些不要推翻：

1. **闭环思路正确**：监测 → 归因 → 优化 → 上线 → 回滚，和赛题原文的五个环节完全对齐。
2. **实验纪律意识**：强制所有实验进 SwanLab、"不靠手动补"，抓住了"记录即交付物"这个要害。
3. **成本账本**：GPU 秒 / 标注数 / Token 三项累计，和客观分口径一致。
4. **合成漂移流**：渐变/突变/复发/label shift 四类，说明已经想到"不能只靠公开验证集"。
5. **对照实验矩阵**：静态 / 周期重训 / 触发式 / 两层自进化，正是主观分"技术路线论证"要的东西。
6. **受控 RSI 边界**：白名单、幅度、次数、kill-switch、审计日志，五件套齐全。
7. **问题清单**：11-07 那 7 条提问质量很高，几乎覆盖了所有未知数。

> 这份 plan0 的**技术判断**是好的，问题主要出在**时间、结构和可执行性**。

## 二、plan0 的六个硬伤

### 硬伤 1：时间轴整体晚了 3 周（致命）

见 `01_赛程与关键节点.md` 第五节。plan0 按"12-27 线上截止"规划，
实际企业赛是 11-26 ~ 12-05，线上提交大概率 **12-02 左右**截止。

**后果**：按 plan0 执行，到 12-05 时我们连镜像都还没做——直接出局。

### 硬伤 2：没有"资格确认"这一步（致命）

plan0 第一条是"扫二维码进群"，但没有**核实报名是否已经提交**。
官方通知的初始报名截止是 **11-07 / 11-09**，今天 11-11。
如果没报名，后面所有工作都没有意义。而且报名后**不得变更成员**。

**修正**：plan1 新增 **Phase 0（11-11，今天）**，第一件事就是确认报名与推荐状态。

### 硬伤 3：把"未知"当成了"已知"

plan0 的日期表标题写着"外部依赖日期（PDF 未给，先去群里换回来）"，
但下面的执行清单却按这些**猜测日期**排期（例如 12-06 拿 PyTRiO 额度）。
一旦猜错（实际全错），整张表失效。

**修正**：plan1 把计划分成**两栏**——
- 「已确定」：官方给了的，写死；
- 「假设」：未确认的，单独列表 + 到期日 + 若假设不成立怎么办（Plan B）。

### 硬伤 4：阶段之间没有依赖关系，也没有判据优先级

plan0 每个阶段都有"判据"，但判据之间是并列的，看不出**哪条不过就必须停下来**。
例如 11-13~11-16 同时要做基线、evaluator、账本、合成流四件事，
没有说明"如果只能做一件，做哪件"。

**修正**：plan1 给每个阶段加 **P0/P1 判据**（P0 不过不许进下一阶段），
并明确**最小可交付垂直切片**（vertical slice）：一条流 → 一个基线 → 一条 SwanLab 记录。

### 硬伤 5：安全机制排得太晚

plan0 把"受控 RSI 边界"放在 11-24~11-30。但：

- 企业赛 11-26 就开赛；
- 安全可控是**主观分四个维度之一**；
- 一旦系统在没有 kill-switch 的情况下跑了半个月，"补"安全机制等于重构。

**修正**：受控机制**从 MVP 第一版就带壳**（哪怕只是配置项 + 一个 `if`），
11-22 前补齐五件套，之后只做增强。

### 硬伤 6：缺少"人"的维度

5 个人怎么分工、谁对哪个判据负责、每周怎么同步、决策怎么留痕——plan0 一个字没有。
4 人以上没有分工，实际执行时会出现"大家都在做 baseline，没人写镜像"。

**修正**：plan1 增加**角色表**（系统/数据评测/建模/Agent/实验管理）、
**每周例会**、**决策日志**、**风险登记表**。

## 三、plan1 相对 plan0 的具体改动

| # | 改动 | 理由 |
|---|---|---|
| 1 | 时间轴按 11-25 / 12-05 / 12-26 重排，压缩为 4 个阶段 + 决赛准备 | 官方日期 |
| 2 | 新增 Phase 0：资格与信息（11-11） | 报名截止已过 |
| 3 | 每个阶段拆成 P0（阻塞）/ P1（加分）两级判据 | 避免"全都重要 = 全都不重要" |
| 4 | 新增"垂直切片优先"原则：先端到端跑通，再优化单点 | 15 天做不完完美系统 |
| 5 | 受控 RSI 五件套提前到 MVP，并定义为**架构约束**而非 feature | 评分项 + 返工成本 |
| 6 | 新增角色分工表（5 人）与 RACI | 可执行性 |
| 7 | 新增「假设台账」与 Plan B（PyTRiO 不来 / 27B 不能离线 / 数据包延期） | plan0 假设全错 |
| 8 | 新增「目标函数」定义：约束下最小化单位增益成本，而非最大化精度 | 客观分口径 |
| 9 | 新增「对照实验矩阵」的**最小可行版本**（4 组 × 3 种子），并规定每组必须进 SwanLab | 主观分证据 |
| 10 | 新增「答辩证据链」：每条主观分维度对应一个可演示产物 | 12-05 答辩 |
| 11 | 新增「不要做的事」清单 | 防止团队跑偏 |
| 12 | 保留 plan0 全部技术动作，只重排时间与优先级 | 不推翻已有判断 |
