## 1. 续训协议是什么（官方 `TRAINING_GUIDE.md` 的四条硬规定）

"续训"不是"重新训练"，是**从上一轮的检查点接着训，并且把这一轮的证据写下来**。

| 规定 | 命令/字段 | 为什么这么定 |
|---|---|---|
| 第一轮从官方基线接着训 | `--from-baseline checkpoint.npz` | 保证起点一致，成绩可复现 |
| 后续轮从上一轮接着训 | `--resume round-1/checkpoint.npz` | 同上，且能追到"这轮从哪来" |
| **每轮必须新目录** | `--output round-2` | 不许覆盖旧证据 |
| **每轮唯一编号** | `--stage-id round-2` | 平台和记录靠它对账 |

`checkpoint.npz` 里不只有权重，还有：**Adam 一阶/二阶矩、累计步数、随机种子、输入标准化参数、目标缩放参数**。
续训会恢复这四样，而不是重新拟合。原因：**如果每轮重新算标准化，成绩变化就分不清是"模型变好"还是"尺度变了"**。

其他硬约束（违反就是无效训练）：

- 标准化/缩放统计量**只在初始训练集拟合**，续训沿用（validation 不能参与）
- `public/validation.jsonl` **不能合并进训练集**
- `training.json` 里 `parent_checkpoint_sha256` 必须对上实际起点，`final_steps` 必须比上一轮大
- 改网络结构/输入维度/任务时，必须做**兼容的权重迁移**并说明，不能把新模型声称成"续训"
- **平台会独立跑预测**，你 `training.json` 里自报的指标不算分

## 2. 一轮的七步（照着做，每轮都一样）

```
① 观测  → ② 诊断 → ③ 决策 → ④ 训练 → ⑤ 验证 → ⑥ 采纳/回滚 → ⑦ 记账
```

| 步 | 做什么 | 产出 | 判据 |
|---|---|---|---|
| ① 观测 | 看当前模型在最近一段数据上的误差、漂移统计 | `psi`、`error_gap`、滑窗 MAE/RMSE | 误差是否在涨 |
| ② 诊断 | 是漂移吗？属哪一类 | `covariate / concept / label / none` | 决定该用哪种动作 |
| ③ 决策 | 动还是不动，动哪个 | `Action(kind=...)` | 过白名单 / 预算 / 幅度上限 |
| ④ 训练 | 按协议续训一轮 | `round-N/{checkpoint.npz, training.json, history.jsonl}` | 命令跑完、目录是新的 |
| ⑤ 验证 | **同一 validation** 比新旧 | 新旧 RMSE/MAE | 新模型是否更好 |
| ⑥ 采纳/回滚 | 更好 → 采纳；不更好 → 丢弃并写原因 | `adopted: true/false` | 差异 > 噪声阈值 |
| ⑦ 记账 | SwanLab + 审计行 | run 链接 + `audit.jsonl` 一行 | 记录能复查 |

**为什么不许"跳过 ⑤ 直接采纳"**：我们的实测噪声是分钟级的，凭感觉觉得更好，多半是噪声。**必须在同一批样本上比。**

## 3. 具体命令（以 B 为例）

```bash
cd data/raw/official_b

# 第 1 轮：从官方基线接着训
python -m baselines.train --profile B \
  --train public/train.jsonl --validation public/validation.jsonl \
  --from-baseline checkpoint.npz \
  --epochs 5 --stage-id round-1 --output round-1

# 第 2 轮：从第 1 轮的产出接着训（注意是 round-1/checkpoint.npz）
python -m baselines.train --profile B \
  --train public/train.jsonl --validation public/validation.jsonl \
  --resume round-1/checkpoint.npz \
  --epochs 5 --stage-id round-2 --output round-2

# 每轮结束：用新检查点跑预测，核对输出格式
python -m baselines.predict --checkpoint round-2/checkpoint.npz \
  --input public/validation.jsonl --output round-2/predictions.jsonl
```

每轮跑完**必须看三个文件**：

- `round-N/training.json`：`validation_before` vs `validation_after`、`final_steps`、`parent_checkpoint_sha256`
- `round-N/history.jsonl`：逐 epoch 曲线，看有没有发散
- `round-N/checkpoint.npz` 是否存在且非空

## 4. 每条动作在循环里的位置

| 观测结果 | 该做什么 | 成本 | 风险 |
|---|---|---|---|
| 误差平稳、PSI 小 | `none`：不训，只记录 | 0 | 无 |
| 误差在涨、特征分布偏了（covariate） | 续训几轮（`retrain`） | 低 | 过拟合验证集 |
| 误差涨但特征没变（concept） | 用近期数据加权续训 | 低 | 抖动 |
| 换了工况/轴承（大规模偏移） | 先检查输入尺度，再考虑 `swap_model` | 中 | 误判 |
| 连续两轮变差 | **回滚**到上一轮 checkpoint | 0 | 无 |

## 5. 接下来 5 天的轮次排期

| 轮 | 做什么 | 假设 | 验收标准 |
|---|---|---|---|
| round-1 | 官方基线续训 5 epoch | 官方给的点已经不错，小步微调够用 | val RMSE **< 666.9**（官方那轮的结果） |
| round-2 | 从 round-1 继续 + 调学习率/epoch | 学习率偏大导致 MAE 反复 | RMSE 再降，且 MAE 不退化 |
| round-3 | 加"近期数据加权" | 晚段样本更接近失效，权重应该更大 | 末段误差下降 |
| round-4 | 换更好模型（我们的 HGB：659.2）作为挑战者 | 树模型比 865 参数的 MLP 强 | **同一 validation 上 < 659.2** |
| round-5 | 复测 + 打包 | 结果可复现 | 两 seed 差异 < 噪声 |

> 竞争关系要讲清楚：官方基线 681.2 / 官方续训一轮 666.9 / 我们的 HGB 659.2。
> **659.2 是当前擂主**，后面每一轮都是打它。

## 6. 我们系统与协议的对照（答辩可直接讲）

| 官方协议概念 | 我们的系统里对应什么 |
|---|---|
| `stage-id` | 一次 `run` / 一个 SwanLab run 名 |
| `checkpoint.npz` | `experiments/<run>/model.pkl` |
| `training.json` | `<run>/summary.json` + `cost.json` |
| `history.jsonl` | `metrics.json`（逐步记录） |
| `parent_checkpoint_sha256` | `summary.json` 的 `parent` 字段 |
| `--from-baseline` / `--resume` | harness 里的 `promote` 时保存冠军、`rollback` 时载回 |
| "平台独立跑预测" | 我们镜像 `docker run --network none` 一条命令跑完并输出 |

**答辩一句话**：官方协议规定"怎么安全地迭代"，我们的 harness 规定"什么时候该迭代、什么时候该退回去"。
两者拼起来，就是完整的自进化闭环。
