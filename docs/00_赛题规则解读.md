## 二、赛题要解决什么（原文第 2 页）

工业模型（设备故障诊断、剩余寿命预测、质量检测）已经进入**产线长期运行**阶段。
工业数据随时间变化 → 模型输入分布、输入-输出关系**漂移** → 模型"失准"，出现误报、漏报、质检失效。

"一次训练、长期有效"的传统建模方式不成立。

同时，大模型智能体已经具备**写代码、调度训练、读实验记录并据此决策**的能力，
"由 AI 驱动模型持续优化"正在走向工程实践。

**本赛题目标**：构建"**工业模型自进化系统**"，推动 **RSI（Recursive Self-Improvement，递归自我改进）**
在真实工业场景落地。选手基于官方数据包，在漂移数据流上**自动维持并提升模型性能**，并**自主判断、论证技术路线**。

实现方式二选一（可组合）：

- **持续微调**：模型层自迭代
- **智能体 Harness**：由工具/技能组合驱动，策略层自改进

鼓励做到"**模型层自迭代 + 策略层自改进**"的**两层自进化**。

👉 解读：
- 这不是一个"训个模型"的比赛，而是一个"**运维一个模型**"的比赛。
- 评分里"论证技术路线"是明写的——所以实验对照组、消融、成本曲线本身就是**作品的一部分**，不是附加材料。
- 两层自进化 = ①模型权重/超参在变；②**决定怎么变的那套策略**也在变（例如阈值、重训触发条件、选哪个模型）。

## 三、考察点（原文第 2 页）

重点考察：

1. 漂移监测与归因
2. 技术路线判断与论证
3. 自动化系统工程
4. 实验管理与可观测性
5. 受控自改进与安全

在**有限算力与标注预算**下，通过合理的**更新决策机制**、**规范的对照实验**与**成本收益分析**，
提升系统的**长期稳定性**与**迭代效率**。

👉 解读（对应到我们要交付的东西）：

| 考察点 | 交付证据 |
|---|---|
| 漂移监测与归因 | 监测模块 + 归因报告（covariate shift vs concept drift） |
| 技术路线判断与论证 | 静态 / 周期重训 / 触发式 / 两层自进化 的对照矩阵 |
| 自动化系统工程 | 一条命令跑完一条流；无人工干预闭环；Docker 镜像 |
| 实验管理与可观测性 | SwanLab 全量记录 + 看板 + 成本账本 |
| 受控自改进与安全 | 白名单、幅度上限、次数上限、kill-switch、审计日志 |

关键约束（原文第 3 页）：

> 提交的模型配置与 Harness 系统镜像中，**驱动 Harness 的大模型必须选用**：
> ① 选手通过 PyTRiO 平台训练得到的模型，**或** ② PyTRiO 的 **Qwen3.8-27B** 模型。

👉 解读：
- **校赛阶段拿不到 PyTRiO 额度**（原文第 5 页明确"校选赛阶段不提供额度"）。所以校赛版本必须能用**本地开源模型或规则引擎**跑通，把 LLM 后端做成**可替换接口**；企业赛再切换。
- 这条也意味着：**不能用 OpenAI/Claude 等外部 API 当最终方案**（离线评测环境没有外网）。
- "驱动 Harness 的大模型"是**被评测对象的一部分**，所以它的推理成本（Token）计入客观分。

## 七、必须完成的两项核心任务（原文第 3 页）

### 任务 1：工业模型自进化系统开发

基于官方数据包**公开部分**，完成系统开发、训练与调优。系统需具备自动完成
**"漂移监测 → 诊断归因 → 实验优化 → 评估上线 → 回滚"** 闭环的能力。

鼓励实现"模型层自迭代 + 策略层自改进"的两层自进化（**受控 RSI**）机制。

### 任务 2：实验记录与提交

- **全部**训练、微调、调整与评估实验，须按《实验记录规范》在云端实验记录平台**完整记录**
- 企业赛第一阶段线上提交截止前（以赛题组通知为准），提交**模型配置 + Harness 的系统镜像**
- 评测方式：赛题组在**指定设备**上，以**统一、离线的运行环境和资源限制**，在**隐藏测试数据集**上正式评测
- **系统须无人工干预地自主运行**，自动维持并提升工业模型在测试流上的性能

### 提交资料（三件套，原文第 3–4 页）

1. 模型配置与 Harness 的**系统镜像**
2. **完整的云端实验记录链接或查询依据**
3. **系统运行说明文档**

👉 解读：这三件缺一不可。第 2 件意味着 **SwanLab 不是"最好用"，而是"交付物"**——记录断档 = 丢分甚至不达标。

## 八、评分标准（原文第 4 页）

### 8.1 分数构成

**总分 = 客观分 + 主观分**

- **客观分**（评测平台按步骤自动计算）主要考察：
  - **单位增益消耗的算力**（GPU 时长或训练额度）
  - **标注配额**
  - **大模型 Token**
- **主观分**（评审专家独立打分）：
  - 方法设计与技术路线
  - 实验规范与分析深度
  - 安全可控与工业落地
  - 报告与答辩

### 8.2 排名与重跑

- 依正式评测结果生成排行榜，**前 20 支队伍**晋级现场答辩
- 系统因自身原因运行失败，可**申请重新运行一次，取两次中较高成绩**

### 8.3 三条硬门槛（不满足 = 不进排名）

1. 封闭评测中**无人工干预**完成全部阶段并**按时输出**结果
2. 全部训练、微调、调整与评估实验均按《实验记录规范》**留完整记录**
3. 封闭评测**综合性能 ≥ 组委会静态基线**（部署后不再更新的模型）

👉 解读（这是全篇最重要的一段）：

- 客观分考的是 **单位增益成本**，不是绝对精度。公式大概率形如
  `单位增益成本 = 总成本 / max(Δ性能, ε)`，其中
  `总成本 = α·GPU秒 + β·标注条数 + γ·Token`。
  **α/β/γ 的具体权重是未知数，必须去群里问**（见 `open_questions.md` Q5）。
- 既然分母是 Δ性能，**性能增益很小的系统，成本再低也救不回来**；性能高但疯狂重训，会被成本拖死。
  → 我们的目标函数应该是 **"在 Δ性能 ≥ 基线的约束下，最小化成本"**，而不是"最大化精度"。
- 门槛 3 的"静态基线"是组委会定义的，**定义未知**（Q4）。在拿到定义前，我们自建一个"部署后不更新"的基线作为代理指标。
- 允许重跑一次 = 首跑应当用**保守配置**，把激进配置留给第二次。

## 九、设备与环境要求（原文第 4 页）

- **自备设备**：能正常连接云端实验记录平台、有代码运行环境（VSCode 等）
- **开发环境**：**Python 3.10 及以上**；深度学习框架、实验跟踪工具、智能体框架**均不限**
- **数据规模**：官方数据包**规模较小**，且**提供预提取特征**，**基础任务用普通 CPU 即可完成**
- **评测环境**：组委会**指定设备**、**统一离线环境**，不受参赛队本地环境影响

👉 解读：
- "CPU 即可完成"，说明这不是拼 GPU 的赛题，拼的是**决策质量**。
- 但**离线**是硬约束：镜像里必须自带模型权重、依赖、特征提取器，**不能 pip install、不能调外部 API**。
- 我们本地开发可以用 GPU，但**镜像验收必须在一台断网机器上做 dry-run**。

## 十、安全与合规（原文第 5 页）

- **数据与账号安全**：妥善保管云端实验记录平台账号，**不得泄露或转借**；禁止攻击评测平台或获取隐藏测试集
- **模型与代码安全**：提交的系统须具备**受控机制**，防止**无限制的恶意迭代**；不得植入恶意代码或进行**未授权的外部网络访问**
- **知识产权**：作品须原创；引用开源框架/预训练模型须遵守开源许可证

👉 解读：
- "不得转借账号" → **每人一个 SwanLab 账号**，加入同一个团队空间。这是合规要求，不是偏好。
- "受控机制" 是**评分项**也是**安全项**，要能在答辩时演示 kill-switch 和审计日志。
- "未授权外部网络访问" → 镜像里**不要留任何出网代码路径**，评测时也不要尝试联网。

## 十一、把规则翻译成设计约束（速查表）

| 规则原话 | 我们的设计约束 |
|---|---|
| 无人工干预跑完全部阶段 | 一条入口命令；异常必须 fallback 到"保持当前模型"，不能崩 |
| 综合性能 ≥ 静态基线 | 第一天就要有静态基线数字；任何策略上线前先过门控 |
| 单位增益成本计分 | 从第一行代码开始记 GPU秒/标注/Token，按 run 落账 |
| Token 计入成本 | Harness 的 prompt 要短、结构化、可缓存；别让 LLM 每步都调 |
| 驱动 LLM 只能是 PyTRiO 模型/Qwen3.8-27B | LLM 后端做抽象层，校赛用本地模型，企业赛切 PyTRiO |
| 统一离线环境 | 镜像自包含；禁止运行时联网；断网 dry-run |
| 实验记录须完整 | 所有实验走统一 wrapper，禁止手工补录 |
| 受控机制 | 白名单 + 幅度上限 + 次数上限 + kill-switch + 审计日志 |
| 隐藏测试流 | 不能过拟合公开验证集；用合成漂移流做私有测试 |

## 十二、原文里"没写清楚"的地方

7. 评测平台 SDK 文档 + 公开集 schema
8. 隐藏测试流的漂移形态与时长
9. 离线评测机上是否预置 Qwen3.8-27B 权重（这决定镜像要不要塞 27B）
